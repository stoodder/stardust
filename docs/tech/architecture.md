## 1. Stack

| Tool | Version (Nov 2026) | Role |
|---|---|---|
| **Node** | ≥ 22.6 (22 is the Claude Code cloud default; 24 also fine) | Dev tooling. `tools/*.ts` run through Node's type stripping: native from 22.18, and the npm scripts pass `--experimental-strip-types` so any Node 22 works. `npm run sim` and the docs check rely on it. |
| **TypeScript** | 7.0.x (`typescript`), strict | Language and type checking (`tsc` is the native Go compiler in 7.x) |
| **Vite** | 8.x | Dev server and production bundler |
| **Phaser** | **4.2.x** | Rendering, input, animation, cameras, filters (WebGL) |
| **Preact** + `@preact/signals` | 11.x / 2.x | DOM UI overlay (HUD, menus, dialogue) |
| **Vitest** | 5.x | Unit, sim, and content tests |
| **Playwright** (`@playwright/test`) | 1.x | Browser smoke tests and screenshots |
| **oxlint** + `oxlint-tsgolint` | 1.x / 7.x | Linting, including type-aware rules |
| **Prettier** | 3.x | Formatting |

Output is a **static site** (HTML + JS + CSS, with no backend), playable in a desktop browser. Input and layout are designed so that touch can be added later (D001 #8).

### Why Phaser 4, not Phaser 3

- **Phaser 4 is the current stable line.** 4.0.0 shipped on 2026-04-10. 4.1.0 and 4.2.0 followed, and 4.2.1 is npm `latest`. Phaser 3 is the legacy line. We have no v3 code to migrate, so there's no reason to start on the older line.
- **Its renderer suits our look.** The v4 WebGL renderer is faster, and its unified filter system gives us camera bloom and glow (`Phaser.Actions.AddEffectBloom`, internal and external filters) for the "glowing emissives against inky dark" style. It also has a tint **fill** mode for hit flashes.
- **It's well documented:** an official v3→v4 migration guide, the "Phaser 4 Rendering Concepts" guide, and updated API docs.
- **The risk is training data.** Most tutorials, and most of what agents remember, target Phaser 3. **Agents must check the v4 API before using anything they remember from v3.** Known traps:

| Phaser 3 habit | Phaser 4 reality |
|---|---|
| `this.make.graphics().generateTexture()` / `Create.GenerateTexture` for pixel art | `Create.GenerateTexture` and the built-in palettes are **removed**. We bake our own textures (`textures.addCanvas` plus frames). |
| `roundPixels` defaults to `true` | Defaults to **`false`**. We set `roundPixels: true` explicitly. |
| `setTintFill(color)` | Removed. Use `setTint(color)` plus `setTintMode(Phaser.TintModes.FILL)`. |
| `preFX` / `postFX` | Replaced by `filters` (internal and external lists). |
| `RenderTexture.draw()` draws immediately | `DynamicTexture`/`RenderTexture` buffer commands until you call **`.render()`**. |
| `Phaser.Geom.Point` | Removed. Use `Phaser.Math.Vector2`. |
| `Phaser.AUTO` with Canvas fallback | The Canvas renderer is deprecated, and filters need WebGL. We use **`Phaser.WEBGL`**. |
| `setPipeline('Light2D')` | `setLighting(true)` (we don't use Phaser lights; see [art-direction.md §7](../art/art-direction.md#7-vfx)). |

### Why TypeScript 7 plus oxlint (not typescript-eslint)

TypeScript 7.0 (July 2026) is the native compiler: same language, and roughly 10× faster type checks. It ships **no programmatic API yet**, so typescript-eslint can't run on it. oxlint's type-aware mode (`oxlint-tsgolint` v7, built on TS 7.0.2) covers almost all of typescript-eslint's type-aware rules and is much faster. Vite and Vitest only strip types and never call `tsc`, so they're unaffected.

**Fallback:** if a tool we need breaks on TS 7, pin `typescript@6.0` and switch to `typescript-eslint`. Record that as a decision.

## 2. The hard boundary: sim vs render

```
               ┌──────────────────────────── browser ────────────────────────────┐
               │                                                                 │
  input ─────▶ │  render/ (Phaser)      ui/ (Preact DOM)      story/   audio/     │
               │      │   ▲                 │    ▲              ▲         ▲       │
               │      │   │ read-only       │    │ view models  │ events  │ events│
               │      ▼   │ state           ▼    │              │         │       │
               │  ┌─────────────── app/ (host: loop, routing) ───────────────┐   │
               │  │   commands ──▶  sim.enqueue()     sim.step() × N         │   │
               │  │   events   ◀──  sim.drainEvents()                        │   │
               │  └──────────────────────────────────────────────────────────┘   │
               │                         sim/  (pure TS, deterministic)          │
               └─────────────────────────────────────────────────────────────────┘
```

**`src/sim/` is pure TypeScript.** It never imports Phaser, the DOM, `render/`, `ui/`, `audio/`, `meta/`, or `balance/`, and never uses `Date`, `Math.random`, `performance`, timers, or `localStorage`. This is enforced three ways:

1. **Separate tsconfig.** `tsconfig.pure.json` covers `src/sim`, `src/content`, `src/story`, `src/balance`, and `src/shared` with `"lib": ["ES2023"]` and `"types": []`. Any DOM global (`window`, `document`, `HTMLCanvasElement`) is a **type error** there.
2. **An architecture test** (`src/shared/architecture.test.ts`) scans the imports (static, re-export, dynamic `import()`, `require`) of every file in `src/` and fails on any edge the [allowed dependencies](#4-other-modules) forbid: pure modules may import no packages (only `vitest`, in tests) and only the modules they depend on; `render`, `ui`, and `audio` reach `sim` only through `sim/index.ts`. It also scans the code the sim executes, `src/sim/`, `src/shared/`, and `src/content/rules.ts` (comments and strings excluded), for the banned `Math` members below, any `Math` use other than `Math.<member>` (so aliasing can't hide a ban), and the globals `Date`, `performance`, `setTimeout`, `setInterval`, `requestAnimationFrame`, `localStorage`, and `globalThis`. This is the authoritative check.
3. **Lint** (`no-restricted-imports`, `no-restricted-properties`, and `no-restricted-globals` in `.oxlintrc.json`) gives fast editor feedback.

Rendering **reads** sim state and **sends commands**. It never mutates sim state.

### Determinism

- Same content + same map + same seed + same command list ⇒ the **same outcome**, on the same JS engine. That's what tests, balance sims, checkpoints, and reproducible bug reports need. Bit-exact results across browsers aren't a goal (there's no multiplayer or server replay).
- **Fixed timestep: 60 ticks per second.** `TICK_HZ = 60` (`src/shared/time.ts`, with the seconds → ticks conversions). Sim time is an integer `tick` counter. Content is authored in seconds and tiles, and converted to ticks once at content compile time.
- **Seeded RNG:** `sfc32` (128-bit state as four plain numbers, so it hashes and serializes) in `src/shared/rng.ts`. The sim derives one **stream per system** from the run's seed (`state.rng.waves`, `state.rng.towers`, …, each `forkRng(root, '<system>')`), so adding a random roll in one system doesn't shift every other system's results. `forkRng` reads its parent without advancing it, so adding a stream doesn't shift the others either. Use the integer helpers (`nextInt`, `nextIntBetween`, `chance`) rather than scaling floats yourself. Cosmetic randomness (particles, Hollow glitches, bark choice) uses separate render-side or story-side RNGs and **never** touches the sim's.
- Iteration order is always array order (entities are processed in ascending slot order). No `for…in` over objects, and no sorting without a deterministic tie-break.
- **Banned in `src/sim/`, `src/shared/`, and `src/content/rules.ts`** (everything the sim executes): `Math.sin`, `Math.cos`, `Math.atan2`, `Math.pow`, and `Math.random` (lint rule plus the architecture test). Their results can differ between engines, and none is needed: use squared distances, precomputed polyline lengths, and `x * x`. Lead targeting solves along the route's `dist`, not with angles.

### Entity model: typed pools, not an ECS

We have about 5 entity kinds and at most a few hundred live entities. A generic ECS would be more machinery than it's worth. **The simplest thing that works:**

- One **typed pool per kind**: `towers`, `enemies` (including neutral units such as Gerald, flagged `neutral`), `projectiles`, `zones` (ground effects, ability areas, and song auras), and `allies`. Each pool is a preallocated array of plain objects with every field initialized (monomorphic shapes), plus a free list.
- **Allies** are every friendly non-tower unit ([design/maps.md §5.4](../design/maps.md#54-allies-on-the-map)). Each has an `allyKind` (`swarmling`, `leaper`, `refugee`, `bearer`, `singer`, `bricks`, `militia`, `ward`), a movement mode (`route`, `post`, `owner`, or `stationary`), an optional attack (Bricks and militia), an optional song aura (singers, bearers), and a **vulnerability**: `never` (swarmlings, leapers, militia, wards, Pebble, Old Thrum), `hush` (refugees, singers, bearers), or `scripted` (Bricks in A3M3: Hollow units stop at his post, but his health bar follows a per-wave timeline in map data, never the player's DPS). Enemies never target towers.
- **Ally targeting.** Ally attacks never target units whose wave group is tagged `quiet_wave`, `youngling`, or `fleeing` (`WaveTag`, [§3 Data shapes](#data-shapes)).
- **Hushing:** a non-boss Hollow unit hushes at most one `fleeing` enemy or `hush` ally and turns Heavy. The fleeing and hush rules (tell, heal, speed, the Maw's gather) have one home, [design/enemies.md](../design/enemies.md) §5.4. In code, the victim is removed and the unit sets `hasHushed = true` so it can't hush again.
- Each entity has a `slot`, a `uid` (a monotonic integer from one run-wide counter, `state.nextUid`, never reused within a run; `0` marks a free slot), and an `alive` flag. Killing an entity (`poolKill`) clears `alive` but keeps the uid, so later systems in the same tick can still name it in events. `cleanup` returns dead slots to the free list at the end of the tick (`poolReleaseDead`), and `poolAlloc` resets every field from the kind's frozen blank when it reuses one. A full pool grows by one slot rather than failing. The pool code is `src/sim/pool.ts`; the entity shapes and blanks are `src/sim/entities.ts`, and each behavior task adds the fields it needs there.
- Entities hold a **direct reference to their compiled definition** (`def: CompiledEnemyDef`; towers also `tierDef`, the current tier), resolved at spawn, so hot loops never look up string ids. Entities refer to **each other only by uid** (`targetUid`, `towerUid`), never by object reference, so sim state has no cycles and `hash()` can walk it.
- Status effects ([design/enemies.md §2.4](../design/enemies.md#24-status-effects)) are **fixed fields** (`chillPct`, `chillMul`, `chillTicks`, `soakedTicks`, `corrodedStacks`, `corrodedTicks`, `markPct`, `markTicks`, `pinnedTicks`, `pinImmuneTicks`, `stasisTicks`, `stasisImmuneTicks`, `unnervedTicks`, `revealedTicks`, and on towers `jammedTicks` and `jamImmuneTicks`), not dynamic lists. Towers also carry `builtTick` and `firstFiredTick` for the misclick-grace refund ([design/core-loop.md §2.3](../design/core-loop.md#23-credits-the-in-map-currency)); for pulse and aura towers, `firstFiredTick` is the first pulse that affects an enemy. Enemies carry their ability state the same way (`abilityTicks`, `abilityCount`, `paceMul` (the abilities' speed multiplier, which movement reads), `burrowed`, `huddleUid`, and for a boss `bossPhase`, `invulnerableTicks`, and `leaving`; Act II's `hushTicks`, `hushUid`, `heavy`, `skittishTicks`, `pulseTicks`, and `blinkTicks`), and a neutral unit (Gerald) is an enemy whose definition says `neutral`. Each tower also has `holdFire` and `spareRunners` booleans (Hold Fire and the targeting filter, [§ Commands](#commands-input-into-the-sim)), `spec` (`'a'`, `'b'`, or null below tier 4), `linkMask` (its active links, bit *i* = the *i*-th link in the compiled link registry), and the Conductive link's extras, `bonusJumps` and `linkSoakedTicks` (recomputed with its bonuses). Entity fields are scalars or frozen content, never mutable objects or arrays: `poolAlloc` resets a slot with `Object.assign` from the frozen blank, which would share them.
- Enemies follow **predefined routes**. Map data gives ground paths and rift lanes as ordered tile sequences, and air lanes as polylines ([design/maps.md §4](../design/maps.md#4-paths-and-air-lanes)). Compile turns each into a polyline through tile centers with precomputed cumulative lengths. An enemy stores `dist` (tiles traveled) and `seg` (the segment `dist` lies on), and `x, y` are derived from those each tick (`src/sim/path.ts`: `placeOnRoute`, `pointAt`, `segmentAt`). A spawned enemy starts at its spawn tile's center (`dist` 0) and leaks on the tick it reaches the core tile's center. Movement adds `speedTilesPerTick × chillMul` to `dist` each tick, using only `+ − × ÷` on doubles (bit-identical on every engine), with a 1e-9-tile arrival tolerance so float sums don't land a tick late. `dist` also gives "first / last" targeting and lead targeting (predict `dist + speed × flightTicks`, then `pointAt`) for free.
- Systems are **plain functions** `(state: SimState, ctx: TickContext) => void`, run in a fixed order:

All are integers.

**Combat** (`src/sim/combat/`, the `status`, `towers`, and `projectiles` systems) implements those rules. The details the design docs leave to code:

- **One damage entry point.** Every hit (tower shot, shell splash, pulse, and the Orbital Strike) goes through `applyDamage(state, enemy, amount, type, source, hit?)` in `combat/damage.ts`: the [enemies.md §2.3](../design/enemies.md#23-damage-pipeline) pipeline, then the kill. `source` is a `DamageSource` (`{ kind: 'tower', uid }`, `{ kind: 'ability', slot }`, or `{ kind: 'ally', uid }`); `hit` carries `armorPierce`, `ignoresArmor`, `isDoT`, and `beamTickSec`, and a `CompiledAttack` satisfies it. On-hit statuses apply after the hit's damage (`applyEffects`), so a Soak never boosts the hit that applies it. A kill (`killEnemy`) is the one place kills are booked: `skitterkinKilled`, `killsByEnemy`, the bounty, and `EnemyDied { killer, bounty, x, y }`, then `SackBurst { route, dist, young }` for a carrier (the Brood Hauler, `EnemyDef.carrier`): its young are render-only and never sim units.
- **HP is fractional** in the sim (the pipeline multiplies), and an enemy at or below `DEAD_HP_EPS` (1e-9) HP is dead, so float residue never costs an extra shot.
- **Targeting** (`combat/targeting.ts`) scans in ascending slot order on squared distances. A single-target tower picks by priority whenever it's ready to fire, and between shots keeps its target while it stays alive, hittable, and in range (so `targetUid` is always current for render). With no minimum range, distance 0 is in range (a flyer over the tower).
- **Timing.** A tower fires on a tick whose `cooldownTicks` starts at 0, then waits `cooldownTicks`. A new tower **deploys** first ([design/core-loop.md §2.5](../design/core-loop.md#25-building-upgrading-selling)): `build` sets its cooldown so its first shot or pulse comes exactly `TOWER_DEPLOY_SEC` (0.5 s, `content/rules.ts`) after the build tick. Upgrades don't reset the cooldown. Spin-up runs from acquiring a target after having none. A pulse tower waits at 0 until an enemy is in range, so its first pulse always affects one (misclick grace). A lobbed shell lands exactly `flightTicks` after the tick it fired, after that tick's movement, so a lead shot at a target holding its speed lands on its center. A Chilled of *N* ticks slows exactly *N* movement ticks.
- **Flak** (Skyhook, `kind: 'projectile'`): a straight shot at `speedTilesPerTick` to the **intercept point** (`interceptInto` in `systems/towers.ts`): it times the flight to the target's position, predicts where the target will be after that long at its current speed (`pointAt(route, dist + speed × ticks)`, as lead targeting does), re-times to that point, and predicts once more, so a target holding its speed is exactly at the aim point when the shot lands. The aim point is fixed when it fires (not homing), and it bursts there like a shell. With no splash, a shot hits only its target.
- **Homing and volleys** (Seeker Swarm, T407b; a projectile's `homing` and `volley`): a volley fires `volley` shots on one tick, each at its own target where it can (`pickTarget`'s `exclude` list: the tower's target, then the next best by priority; with too few, the extras go round them again). A homing shot is steered by the `projectiles` system each tick at `speedTilesPerTick` straight at its target's position, retargets to the nearest hittable non-neutral enemy within `HOMING_RETARGET_TILES` (3) when its own dies, leaks, burrows, cloaks, or leaves, and fizzles (a `ProjectileHit` with `hits: 0`) when it finds none or after `HOMING_LIFE_TICKS` (3 s); for it `flightTicks` is the lifetime, not a flight. The rules are `systems/projectiles.ts`'s header.
- **Charges** (Capacitor Bank, T407b; `attacks/charge.ts`): the tower's `chargeTicks` grows each tick it holds a target and discharges at the charge time (rate bonuses shorten it, `bonusChargeTicks`); a dead or leaked target swings the charge to a new one, an escaping target or an empty range fizzles it, Hold Fire vents it. A discharge emits `ProjectileFired` (`kind: 'charge'`) and one `ProjectileHit`; a fizzle emits nothing (render reads `chargeTicks`).
- **Neutral units** (Gerald, `combat/neutral.ts`): targeting treats one like any enemy on its layer. A shot aimed at it (hitscan, or a shell or burst fired at it that lands with it inside) plinks off: no damage or status, `NeutralHit`, and `stats.neutralHits` + 1. Every other area hit (bursts, pulses, chain jumps) skips it, and the damage pipeline never sees it. At its route's end `movement` removes it with `NeutralExited` (no integrity, tag, or Perfect Core cost; `medals.ts` `leakedThisTick` skips it). It still counts toward its wave's `remaining`, so a wave resolves once he has left.
- **Shells** copy everything the impact needs at fire time (damage, armor fields, splash, layers, effects), so selling or upgrading the tower mid-flight changes nothing. Splash hits only the layers the firing tier targets, and every victim is chosen before any damage lands.
- **Commander abilities** (`systems/abilities.ts`, [design/core-loop.md §3](../design/core-loop.md#3-commander-abilities)). Slot 1 holds `abilities.slot1`; slot 2 holds `abilities.slot2` only while `slot2State` is `present` (an `absent` companion's slot is shown dark and can't be used). `applyCommands` hands the `ability` command to `applyAbilityCommand`, which rejects `noAbility` (an empty or absent slot), `abilityOnCooldown` (in ticks or in waves; `abilityReady(state, slot)` asks the same), or `invalidTarget` (for a targeted ability, a missing target, one off the map, or for a segment a tile no ground route crosses; the untargeted `slowAll` and `discount` ignore a target). An accepted cast applies its effect (`abilitySlot` names a zone's source), sets `state.abilityCooldownTicks[slot − 1]` or `abilityCooldownWaves[slot − 1]` to the modified cooldown (unless it's Ready Room's free cast, below), counts `stats.abilityUses`, and emits `AbilityUsed { slot, uid, ability, target }` (`uid` is the first zone's, or 0; `target` is null for an untargeted ability). Each tick the `abilities` system counts every cooldown down and runs the zones, all victims chosen before any damage, through `applyDamage` with `{ kind: 'ability', slot }`:
  - A **strike** (Orbital Strike) lands exactly `delayTicks` after the tick it was cast, before that tick's movement, on every **ground** enemy whose center is within its radius (inclusive, like splash; the strike isn't an air answer in `COUNTER_ANSWERS`).
  - A **segment** (Suppressing Fire) covers the clicked path tile ±`reachTiles` along **each ground route** whose tiles include it (one zone per route; air lanes never), shifted inward at a route's spawn or core so it keeps its length, and padded half a tile at each end so it covers those tiles whole: `distFrom ≤ dist ≤ distTo`. For `durationTicks` from the cast tick, every enemy on it is Chilled `slowPct` each tick (the strongest-chill rule, so it doesn't stack with a Sprinkler; it lingers one movement tick after the enemy leaves), and every 0.25 s it takes `damagePerSec × 0.25` as a **beam tick** (armor prorated, [enemies.md §2.3](../design/enemies.md#23-damage-pipeline)), the last on the zone's final tick: 20 ticks, 100 damage to an unarmored enemy that stays on it. It covers ground-layer units only, so Gerald (an air unit on the ground path) is never slowed or hit.
  - A **field** (Time Dilation, `slowAll`) has no position: for `durationTicks` from the cast tick it Chills every live enemy on the map `slowPct` each tick (air, burrowed, and late spawns included; never a neutral unit), by the same strongest-chill rule. A boss takes it at half strength through `applyChill` (`BOSS_CHILL_MULT`), which is the content's `bossSlowPct`. Render tints the battlefield while a `field` zone lives (T312a).
  - A **discount** (Clearance Sale) makes no zone: it sets `state.discountCharges` to its `charges` and `discountPct` to its `pct` (replacing any left), and purchases spend them (*Waves, economy, and the end of a map* below). Its cooldown is in **waves**: `abilityCooldownWaves[slot − 1]` counts the waves still to start, and the `abilities` system takes one off on the tick each wave starts. A wave that started on the cast's tick before the cast doesn't count (the cast adds one to cancel it); one that starts later that tick does.
  - **Ready Room** (`freeCast` modifiers, each naming a wave): the first cast of each slot while `state.wave` is a named wave (from its start until the next wave starts) starts no cooldown, and `state.freeCastWave[slot − 1]` records the wave whose free cast it used. `freeCastReady(state, modifiers, slot)` tells the HUD.
  - **Modifiers.** `abilityStats(def, modifiers)` applies `abilityStat` modifiers that name the ability (or `'*'`) by the stacking formula: cooldown (`flat` in seconds; at least one tick) and a strike's radius. A cooldown in waves takes the percentages only, `round(waves × (1 + Σ pct))` and at least 1, so Coolant leaves Clearance Sale at 4 waves and a Rapport makes it 3. Companion Rapport is cooldown −15% on its companion's ability, Ability Coolant −5% on every ability, and Orbital Strike Mk II radius +0.5 flat. The HUD reads the same function for the cooldown wipe and the reticle.
  - **The companion slot.** `companionSlot(content, map, picked?)` (`sim/companion.ts`) turns a map's `companion` into SimConfig's `companion`, `abilities.slot2` (the ability whose `companion` field names them) and `slot2State`; on a pick-list map the first is the default. `createSim` refuses a slot 2 without a companion, a companion without a slot, a `present` companion with an empty slot, an ability in slot 2 that isn't that companion's, and an `abilityStat` modifier that names an unknown ability or a radius on a segment.
  - Abilities are ready from tick 0. Cooldowns run on sim time, so an ability aimed while paused (`applyPending()`) lands as if cast on the next tick; an early call cuts the ones in ticks through `reduceAbilityCooldowns` (the wave it starts counts toward one in waves).
- **Allies** (`systems/allies.ts`, system 7b). The map's ally **posts** (`MapDef.allies`: kind, a decor marker, a hitscan attack) spawn on tick 0, in map order, at their tiles' centers, in mode `post` with vulnerability `never` (`AllySpawned`). An ally fires like a hitscan tower (on a tick whose cooldown starts at 0, then waits `periodTicks`) at the **nearest** enemy in range (inclusive, ties to the lowest uid) on a layer it hits, re-picking every shot, and never a unit whose wave group is tagged `quiet_wave`, `youngling`, or `fleeing` (`allyMayTarget`). Its hits go through `applyDamage` with `{ kind: 'ally', uid }`, so bounties and kill counts book as for a tower, and each shot emits `AllyAttacked`. `removeAlly` (for scripts, M3) emits `AllyRemoved`. The headless tracker's invariants (#12) check that no ally attacks or targets an exempt unit, that never-vulnerable allies keep full health, and that allies stay on the map.

**Waves, economy, and the end of a map** (the `waves`, `triggers`, and `cleanup` systems, `applyCommands`, and `src/sim/economy.ts`) implement [design/core-loop.md §2.1–2.5 and §2.9](../design/core-loop.md#2-in-map-loop). The formulas and numbers are in `content/rules.ts` (`waveClearBonus`, `earlyCallBonus`, `SELL_REFUND_PCT`, `MISCLICK_GRACE_SEC`, the tagged bounties). The details the design leaves to code:

- **The schedule** is `state.schedule`: `phase` (`setup` → `spawning` ⇄ `countdown` → `done`, with `held` between `spawning` and `countdown` for a wave that waits for the boss), `waveTicks` (the spawning wave's clock), `countdownTicks` and `countdownTotalTicks` (0 outside a countdown), `countdownWave` (the highest wave whose build phase has begun: 1 in setup), and per wave `startTick`, `remaining` (enemies not yet dead or leaked, unspawned ones included), and `resolved`. Only one wave spawns at a time, because a wave can be called only during a countdown.
- **Spawning.** A wave's spawn clock starts at 0 on the tick it starts (a `callWave` applied by `applyPending()` starts it on the next tick). Group *g*'s *i*-th unit spawns at `delay + i × interval`, groups in parallel and in authored order within a tick, with full `hp` and `shieldHp`, at its route's start. On the last spawn tick the next wave's countdown starts (`CountdownStarted`), and its wave-phase `countdown` triggers fire that same tick. When it reaches 0 the wave starts (`WaveStarted { early: false }`). **A wave with `countdownAfter: 'bossEnded'`** (A1M5's Quiet Wave, D097) waits instead while a boss fight is on (a live boss not yet leaving): the phase is `held`, with no countdown, until the first tick no boss is fighting (driven off, `BossEnded`, or off the map any other way); then its countdown starts as above.
- **`callWave`** in setup starts wave 1 for free. During a countdown it starts the next wave now, credits `earlyCallBonus(wave, countdownTicks, countdownTotalTicks)` (`WaveStarted { early: true, bonus }`), and cuts every ability cooldown by `round(0.25 × countdownTicks)` ticks. While a wave spawns, or the next one is `held`, it's rejected `waveInProgress`; after the last wave starts, `noWavesLeft`. A next wave with a `quiet_wave` group is never called (`quietWave`, no bonus; `nextWaveIsQuiet(state, map)`), so the player sees the Quiet Wave walk in before choosing.
- **Bounties** are credited in `killEnemy` through `payBounty`: the enemy's `bounty`, 1 for a `fleeing` unit, 0 for a `youngling` (`bountyFor`), then the `bounty` modifiers' percentage. Credits are whole, so the fraction that percentage earns carries to the next kill (`state.economy.bountyCarry`). `EnemyDied.bounty` is what was paid. Leaks pay nothing.
- **Sell** refunds `sellValue(tower, state.tick, state.economy.sellRefundPct)`: everything invested while `firstFiredTick < 0` and fewer than 600 ticks have passed since `builtTick`, else `floor(invested × 0.7)` (Resale Value raises the 0.7; float slack makes 0.7 × 180 126). Sim time is ticks, so paused time never counts. The tile frees at once, so a sell and a rebuild can share a tick. Shells in flight still land.
- **Resolution, win, and loss** are `cleanup`'s, at the end of the tick: each enemy that died or leaked this tick decrements its wave's `remaining`. Then integrity 0 loses (`MapLost`, which beats a same-tick win). Otherwise every started wave at 0 resolves, in wave order within a tick (waves overlap, so they can resolve out of order across ticks), credits `waveClearBonus(wave)`, and emits `WaveCleared { wave, bonus }`. When every wave has resolved, the map is won (`MapWon`). Either way `outcome` is set, `step()` does nothing after, and commands are rejected `mapEnded`.
- **Script triggers** fire on the first tick they're reached, in map-event order (`state.scriptFired`). Every trigger the sim runs is monotonic, so `once: false` changes nothing yet. A `cleared` trigger fires on the tick after its wave resolves. An event's `when` is judged once, on that tick: if it doesn't hold, the event is spent without running its actions.
- **Purchase prices.** A build, upgrade, or specialization pays `pay(state, modifiers, tower, base, kind, ctx.scratch.price)`, which charges `purchasePriceInto`'s price: `costFor` (the `towerCost` modifiers), then Rapid Deploy (`firstBuildFree`: a build while `stats.towersBuilt` is 0 costs 0 and spends no sale charge), then Clearance Sale (while `discountCharges` remain, a purchase that still costs credits costs `round(cost × (1 − discountPct))` and spends one charge; at 0 charges `discountPct` resets to 0). The sale multiplies after the modifiers. `invested` grows by what was actually paid, so a sell refunds a share of the discounted price, and a free first build refunds 0.
- **Stats.** `creditsSpent` is gross (builds and upgrades); `creditsRefunded` counts sells, so net spending is the difference. `creditsEarned` counts bounties, clear and early-call bonuses, and script grants.
- **For the HUD** (`sim/index.ts`): `state.schedule` for the countdown, `callWaveBonus(state, map)` for the call button's bonus (0 outside a countdown and for a Quiet Wave), `nextWaveIsQuiet(state, map)` (hide Call while it holds), `sellValue(tower, state.tick, state.economy.sellRefundPct)` for the sell button (or `sellValueInto(…, out)`, which fills a scratch object, for a per-frame read), `costFor(sim.config.modifiers, tower, base)` for list prices and `purchasePriceInto(sim.state, modifiers, tower, base, kind, out)` for what a purchase costs right now (Rapid Deploy and Clearance Sale included), `abilityReady` and `freeCastReady` for the ability slots, `isLinkActive(state, content, id)` and each tower's `linkMask` for its links, and `towerStats(def, tier, tower, sim.config.modifiers)` (`sim/towerStats.ts`) for the tower panel's stat line under the tower's bonuses (with a link's `vsStatus` damage) and the next tier's delta and price, as simulated (rate from the whole-tick cooldown).

#### Medals

**Medals and conditions** (`src/sim/medals.ts`, `src/sim/conditions.ts`) implement [design/progression.md §3](../design/progression.md#3-medals-and-intel) and the medal-exempt rule ([design/core-loop.md §2.7](../design/core-loop.md#27-hold-fire)). The condition grammar is in [story-runtime.md § Conditions](story-runtime.md#conditions).

- **`state.medals`** holds `victory`, `perfectCore`, and `challenge`, each `open`, `forfeited` (it can't be earned this run), or `earned` (at victory). Every change emits `MedalProgress { medal, status }`, always before `MapWon` / `MapLost` on the tick that ends the map.
- **`cleanup` keeps them**, every tick: a dead enemy left at its route's end leaked (`leakedThisTick`); a medal-exempt one (a group tagged `quiet_wave`, `youngling`, `fleeing`, or `medal_exempt`; `MEDAL_EXEMPT_TAGS`) adds to `stats.medalExemptLeaks`, any other forfeits Perfect Core at once, even when its leak cost 0 or Emergency Bulkhead absorbed it. Then `trackConditions` latches `passedMarker` passes in `stats.markersPassed` while this tick's dead are still in their pools, and an open Challenge whose condition has **settled** false (`settledCondition`: a run atom broke) is forfeited. A loss forfeits every open medal. A win earns Victory and an open Perfect Core, and judges an open Challenge with `evaluateCondition` on the win tick (state atoms as they stand, run atoms over the run).
- **A map without a Challenge** (a dev or fixture map; every campaign map has one) leaves `challenge` open and never emits for it.
- **Save ids** are `victory`, `perfect_core`, and the map's `medals.challenge.id` (`medalId`, `mapMedalIds`). At run end `earnedMedalIds(state, map)` lists the earned ones in that order; meta records them and applies the checkpoint rule ([meta-runtime.md § Run end](meta-runtime.md#run-end)). The HUD and briefing read `state.medals` live, and `map.medals.challenge` for the Challenge's `name` and `description`.
- **`HeadlessResult.medals`** is the final `state.medals`; the balance report prints it per run and the `medals` check holds par to the map's `parMedals` ([conventions.md § Balance sims](conventions.md#balance-sims-npm-run-sim)).
- **Optional objectives** (`src/sim/objectives.ts`, T304f; [design/core-loop.md §2.13](../design/core-loop.md#213-optional-objectives)) settle beside the medals. `state.objectives` holds one `ObjectiveStatus` per `map.objectives` entry, in map order: `open`, `done`, or `failed`. Every tick in play `cleanup` settles an open objective whose condition has settled (`settledCondition`): true makes it `done` and runs its `onComplete` actions at once (the same actions as an event's, `runScriptAction`), false makes it `failed`. A win judges the rest with `evaluateCondition`; a loss fails them. Every change emits `ObjectiveProgress { id, status }` before `MapWon` / `MapLost`. `trackConditions` latches the markers objectives watch too. A sell counts `stats.lateSells` when `isLateSell` holds: a wave started after the tower's `builtTick` and the sale isn't a misclick-grace refund. The HUD reads `state.objectives` (or `objectiveStatusById(state, map)`); run end reads `completedObjectiveIds(state, map)` with each one's `intel`, and meta pays it on a win ([meta-runtime.md § Run end](meta-runtime.md#run-end)). `HeadlessResult.objectives` is the final `state.objectives`.

If profiling ever shows object pools are too slow (unlikely below about 2,000 entities), convert a hot pool to struct-of-arrays (`Float32Array` columns) behind the same system functions.

### Commands (input into the sim)

Every player action is a **command**: a plain, serializable object in a discriminated union.

```ts
type Command =
  | { type: 'build';      tile: GridPos; tower: TowerId }
  | { type: 'upgrade';    towerUid: number }               // next tier
  | { type: 'specialize'; towerUid: number; spec: 'a' | 'b' }
  | { type: 'sell';       towerUid: number }
  | { type: 'targeting';  towerUid: number; mode: TargetPriority }
  | { type: 'holdFire';   target: number | 'all'; on: boolean }      // stop firing
  | { type: 'spareRunners'; target: number | 'all'; on: boolean }    // the targeting filter
  | { type: 'clear';      tile: GridPos }                  // send the salvage drone to a wreckage tile
  | { type: 'ability';    slot: 1 | 2; target?: GridPos }  // commander abilities
  | { type: 'callWave' }                                   // call the next wave early
  | { type: 'interact';   marker: MarkerId }               // click a clickable world object (the Peeker rock, A2M3)
  | { type: 'scriptInput'; id: string };                   // the forced single input (SEAL, "Who's there?")
```

- The code is the home of the union as built: [`src/sim/commands.ts`](../../src/sim/commands.ts) holds every command through M2, M3's `clear`, M4's `interact`, and `RejectReason`. The sketch above is the full target; `scriptInput` arrives with its Act III map. `applyCommands` dispatches `specialize` to `src/sim/specialize.ts`, `holdFire` / `spareRunners` to `src/sim/fireControl.ts`, and `clear` to `src/sim/systems/wreckage.ts` (off the map: `invalidTile`; not wreckage, or already queued or cleared: `invalidTarget`).
- The host calls `sim.enqueue(cmd)`, and the command applies at the **start of the next tick**, or immediately through `sim.applyPending()` (below). `enqueue` copies the command, so the caller may reuse its object.
- `holdFire` (a tower uid or `'all'`) stops the tower attacking; it's the plain Hold Fire that C1 uses. A holding tower drops its target, its cooldown keeps running (it can fire the tick it's released), and its links and bonuses are untouched. `'all'` sets `state.holdFireAll` and every live tower's flag, and towers built while it's on start holding; `'all'` off clears every tower's flag, per-tower holds included (the HUD button is a master switch). A uid that names no live tower is rejected `noSuchTower`.
- `spareRunners` is the **"Spare runners" targeting filter** (from A2M1; the rules are in [design/core-loop.md](../design/core-loop.md) §2.6–2.7). With a tower uid it is the per-tower toggle. `'all'` is the global HUD toggle (hotkey Alt+H): it sets `state.spareRunnersAll` and every tower's filter (off clears them all), and towers built while it's on start with it on. A tower with the filter on never *picks*, or keeps, a unit whose wave group has a tag in `SPARE_TAGS` (`fleeing`, `youngling`; `content/rules.ts`) as its primary target (`pickTarget` / `isStillTarget` in `combat/targeting.ts`), and a pulse tower waits until an unspared unit is in range. Splash and chain hits, and a pulse fired for another unit, still land on those units.
- `interact` is accepted only while the marker is clickable (a `setClickable` script action; otherwise `notClickable`), and `applyCommands` dispatches it to `src/sim/clickables.ts`. It is the input half of the clickable-world-object trigger ([story-runtime.md § Map scripts](story-runtime.md#map-scripts-story-driven-sim-changes)).
- The sim validates every command (affordability, a buildable and empty tile, a tower in the loadout, unlocked and not revoked, an ability off cooldown and not revoked). While a forced input is pending, **every command except the matching `scriptInput` is rejected** (`reason: 'forcedInput'`). Invalid commands emit `CommandRejected { cmd, reason }` so the UI can explain.
- The **command log plus the seed reproduces a run exactly.** The sim appends every command it applies, accepted or rejected, to `state.commandLog` as `{ tick, cmd }`, where `tick` is the tick it applied at (a command applied by `applyPending()` after tick *T* logs *T + 1*, the same as one applied at the start of tick *T + 1*). Replaying means enqueuing each entry just before that tick runs. The game keeps the log in memory for checkpoints and so a bug report can include a replayable code (dev builds), and balance-sim builds are just scripted commands.
- **Optional bark buttons** ("Who's there?" in Act I) are not commands. They never change play, so they stay out of the sim and the command log; story handles them ([story-runtime.md § Barks](story-runtime.md#barks)).

### Events (output from the sim)

- During a tick, systems push typed events into `state.events`.
  - **Combat:** `EnemySpawned`, `EnemyDied`, `SackBurst` (a carrier's sack, `sim/carrier.ts`), `EnemyLeaked`, `ProjectileFired`, `ProjectileHit`, `TowerBuilt`, `TowerUpgraded`, `TowerSpecialized`, `TowerSold`, `TowerJammed`, `HoldFireChanged`, `SpareRunnersChanged`, `LinkFormed`, `LinkBroken`, `AllySpawned`, `AllyAttacked`, `AllyRemoved`, `MedalProgress`, `AbilityUsed`, `WaveStarted`, `WaveCleared`, `BossPhase`, `NeutralHit` (a shot on Gerald), `NeutralExited` (Gerald delivered and left: never a leak), `WreckageCleared`, `AssetHit { uid, enemy, lost }` (a leak at a Protect map's asset; it follows an `EnemyLeaked` with leak 0), `AssetLost`, `MapWon`, `MapLost`, `CommandRejected`, `CheckpointReached { wave, tick }` (the tick a retry resumes at; § Checkpoints).
  - **Story-facing:** `ScriptCue { cueId }`, `NotFiringAtSkitterkin { wave }` (at most once a wave, when `ticksSinceFiredAtSkitterkin` reaches `NOT_FIRING_TICKS` (`NOT_FIRING_SEC`, 10 s, in `content/rules.ts`); `state.notFiringAnnounced` remembers it for `state.notFiringWave`, and a new wave re-arms it and restarts the count, T330), `SkitterkinKilledAhead`, `Hushed { hollowUid, victim: 'enemy' | 'ally' }` (the Hollow unit turns Heavy), `RefugeeSaved`, `AllyHealthChanged`, `EnemyLaidToRest { uid, restValue }`, `EnemyScattered`, `EnemyReformed`, `BossEnded { how: 'driveOff' | 'retreat' | 'pivot' | 'layToRest' }`, `ObjectiveChanged`, `ObjectiveProgress { id, status: 'done' | 'failed' }`, `TowerClassUnlocked`, `TowerClassRevoked { tower, refund }`, `TowerClassRestored`, `AbilityRevoked`, `ClickableChanged { marker, on }`, `Interacted { marker, by: 'player' | 'fallback' }`, `ForcedInputRequested { id }`, `ForcedInputResolved { id }`, and `TimerProgress` (secondary timer, emitted on each whole percent).
- After each frame's ticks, the host calls `sim.drainEvents(out)`, which **appends** every event since the last drain to `out` (the caller clears `out`) and empties the sim's buffer. Events wait in the buffer until drained, so a headless runner that ignores them should still drain now and then. The host dispatches the events to subscribers (render views, UI signals, story, audio) through the **typed event bus** in `src/shared/bus.ts` (a tiny `on/off/emit` emitter keyed by event `type`).
- **Inside the sim, systems communicate through state, not events.** Events are output only, which keeps the tick order explicit. Payloads as built are in [`src/sim/events.ts`](../../src/sim/events.ts). `ProjectileHit.reduced` says armor blunted the hit (some victim's armor, after pierce and Corroded, still subtracted: `armorReduces` in `combat/damage.ts`), for the plink. `ProjectileFired` and `ProjectileHit` fire once per attack of every kind (`uid` 0 when no projectile entity exists: hitscan and pulses), so render and audio see every shot. `ProjectileFired` carries what render needs to draw the shot without looking up the tower (which may be sold or upgraded by then): `sprite` (the firing tier's projectile sprite, null for hitscan and pulses) and `flightTicks` (a shell's flight, else 0).
- Events are infrequent compared to per-entity work, so plain object events are fine. Per-entity, per-tick work must not allocate ([conventions.md § Performance](conventions.md#performance-rules)).

### Map scripts

Story moments that change play run **inside the sim** as map data (`MapDef.events`, evaluated by the `triggers` system), so headless runs, replays, and the balance harness see exactly what a player sees. The trigger and action unions, flags in the sim, forced input, revocation, clickable objects, and rest and scatter are specified in [story-runtime.md § Map scripts](story-runtime.md#map-scripts-story-driven-sim-changes).

### Game speed, pause, and the host loop

The sim doesn't know about speed. The host (`createHost(sim)` in `src/app/host.ts`) wraps one sim, and `BattleScene.update(time, delta)` calls its `frame(delta)` once per rendered frame:

```ts
const TICK_MS = 1000 / TICK_HZ;
const MAX_STEPS_PER_FRAME = 4;                   // per 1× of speed
const MAX_FRAME_DELTA_MS = 250;                  // a background tab or a debugger pause
const cap = MAX_STEPS_PER_FRAME * Math.max(speed, 1);
acc += Math.min(delta, MAX_FRAME_DELTA_MS) * speed;   // speed ∈ {0 (paused), 1, 2}
let steps = 0;
while (acc >= TICK_MS && steps < cap) {
  sim.step(); acc -= TICK_MS; steps++;
}
if (steps === cap) acc = 0;                      // drop backlog rather than spiral
if (speed === 0) sim.applyPending();             // build/upgrade/sell land while paused
events.length = 0; sim.drainEvents(events); dispatch(events);   // then the after-frame listeners
```

- **The host's API:** `sim`, `bus` (the drained events, by type), `speed` / `setSpeed(s)` (pausing empties the accumulator, so paused time never banks), `enqueue(cmd)`, `frame(deltaMs)` (returns the ticks stepped; non-finite or negative deltas count as 0), `fastForward(ticks)` (steps exactly `ticks` with no cap and regardless of speed, then dispatches once; `fastForward(0)` applies pending commands without advancing time), `onAfterFrame(listener)` (runs after every dispatch: the HUD's signal sync), and `simMsPerTick()` (a smoothed mean, for `__sd.perf()`). Its unit tests are `src/app/host.test.ts`.
- **One frame, in order:** the host steps and dispatches (views are created and released by the events), then BattleScene positions every view from sim state and redraws the hover, selection, range ring, and placement ghost ([§ Rendering](#rendering)).

- Speeds are 1× and 2×, with 3× an open design question ([design/core-loop.md §2.8](../design/core-loop.md#28-speed-and-pause)). The loop handles any integer speed; 2× is two ticks per 16.7 ms of accumulated time, not a bigger timestep. Pause sets speed to 0. Full-screen dialogue scenes pause; build-phase barks don't ([story/style-guide.md](../story/style-guide.md)).
- **`sim.applyPending()`** is a zero-time, command-only step: it runs `applyCommands` on the queue without advancing `tick` or any other system. Applying commands at the end of tick *T* is identical to applying them at the start of tick *T + 1* (`applyCommands` runs first), so the command log stays replayable without knowing whether the game was paused.
- Rendering shows the latest tick's state with no interpolation. (At 60 Hz ticks this is smooth enough for pixel art; interpolation can be added later if 120 Hz+ displays look juddery.)

### Checkpoints

"Retry from wave N" ([design/core-loop.md](../design/core-loop.md) §2.12) needs no state serialization. A **checkpoint** is `{ wave, tick, commandCount }` (`app/checkpoints.ts`), recorded by the host (`Host.checkpoints`) when the sim emits `CheckpointReached { wave, tick }`. The waves system emits it as the countdown to every `CHECKPOINT_EVERY_WAVES`-th wave begins on a numbered act's map from `CHECKPOINTS_FROM_ACT` on, never on a Holdout (`checkpointAt` in `sim/systems/waves.ts`, rule data in `content/rules.ts`); its `tick` is the state after the emitting tick, and `commandCount` the logged commands below it. The finale will emit it at the start of Phase 2 through its `checkpoint` script action (refused until then).

- **Retrying** (`router.retryFromCheckpoint`, the Results button) re-creates the sim from the lost run's own `SimConfig` (same seed, loadout, and modifiers) and starts the battle with a `Resume` (the checkpoint and its log prefix). The host is in replay mode (`Host.replaying`) from creation: `startBattle` wires the HUD, the dialogue, and the router's listeners, then `host.catchUp()` enqueues each logged command before its tick, steps to `tick`, and dispatches every tick's events as it goes; audio and the scene start after, from the state it reached. A replay that doesn't land on the checkpoint throws (the battle fails to start like any other). Only the **latest usable checkpoint** is offered and retried (`usableCheckpoint` in `app/checkpoints.ts`: one taken before the run's final tick, so a loss on the countdown-begin tick falls back to the earlier one), and a replay that ends the run throws, landing on the campaign screen with the `RETRY_FAILED` notice (D134).
- **The app's story state rebuilds itself from the replayed events**, so nothing double-counts: the dialogue's bark picks (spacing, once-limits, fired triggers), met enemies, Bricks's name tag, radio and cue scenes already played, the HUD's teach counters, and the router's waves, met list, and first leak all see the events again. What the player would see or hear is held back while `replaying` (lines, barks, banners, flashes, notices, announcements). The sim's own state (the asset, objectives, medals' standing) is replayed exactly. The scene, created after, draws towers and enemies from state as always and forms the live links' tethers and the cued props from state (`bindBattleEvents`).
- **The resumed battle** opens paused with a notice. Its run result carries `resumedFromWave` (meta reads it as `usedCheckpoint`: Victory only; the defeat stipend counts waves from it on), its kills are the attempt's (`attemptKills`: the sim's count less `Host.killsBefore`, the count at the checkpoint), and its `checkpointWave` (the latest, replayed ones included) is what a loss offers next ([meta-runtime.md § Run end](meta-runtime.md#run-end)).
- **Cost:** replaying to A2M2's W10 (about 24,000 ticks) takes about 0.1 s headless; with the battle's listeners it stays well under a second, and the finale's longest replay well under 2 s. Checkpoints live in memory for the current run only (open question 1).

### Sim public API

```ts
// src/sim/index.ts (implementation: sim.ts, config.ts, state.ts)
export function createSim<K extends IdSpace = LiveIds>(cfg: SimConfig<K>): Sim<K>;
interface SimConfig<K> {
  content: CompiledContent<K>; mapId: K['map']; seed: number;   // seed: an integer in [0, 2³²)
  loadout: K['tower'][];              // ≤ 4 distinct (hard rule); never contains a revoked class
  companion: CompanionId | null;      // resolved from MapDef.companion (a pick list is resolved before the map)
  modifiers: Modifier<K>[];           // from permanent upgrades, difficulty, veteran mods
  difficulty: DifficultyId;           // 'story' | 'standard'
  abilities: { slot1: K['ability'] | null; slot2: K['ability'] | null; slot2State: 'present' | 'absent' | 'none' };
  scriptFlags: ScriptFlags;           // story flags that map scripts read (story-runtime.md § Map scripts)
  specsUnlocked: K['tower'][];        // towers whose tier-4 pair is unlocked (one purchase, both specs)
}
interface Sim<K> {
  readonly state: DeepReadonly<SimState<K>>;   // the live object, same every tick
  readonly config: SimConfig<K>;
  readonly map: CompiledMapDef<K>;
  enqueue(cmd: Command<K>): void;     // copied; applies at the start of the next tick
  step(): void;                       // one 60 Hz tick; a no-op once the map is won or lost
  applyPending(): void;               // zero-time, command-only step (works while paused)
  drainEvents(out: SimEvent<K>[]): void;   // appends to out, empties the buffer
  hash(): string;                     // 16 hex digits over all state, for determinism checks
}
// src/sim/headless.ts (also exported from src/sim/index.ts)
export function runHeadless<K>(cfg: SimConfig<K>, build: CompiledBuild<K>, opts?: HeadlessOptions): HeadlessResult;
export function createBuildExecutor<K>(sim: Sim<K>, build: CompiledBuild<K>): BuildExecutor;   // beforeTick(), steps, waveCalls
```

- **Id typing.** `K` is the content's id space ([§3 Data shapes](#data-shapes)): the game uses the live registries, tests use `src/sim/__fixtures__/sim.ts` over the content fixture. It types only the API's edges (config, commands, events); inside, the sim runs on plain string ids.
- **`createSim` validates the config** and throws a `RangeError` listing every problem: an unknown map, tower, or ability, a bad seed, or a loadout over 4 or with duplicates. It also checks `abilities.slot2` and `specsUnlocked` name real content. It refuses what it can't simulate yet, rather than ignoring it, per feature: `FEATURE_GATES` in [`src/sim/gates.ts`](../../src/sim/gates.ts) maps each feature (a companion, slot 2, `specsUnlocked`, Story difficulty, each modifier kind with `economy` split by stat, each attack kind or on-hit status on any tier a loadout tower can reach (its specs included once unlocked), each ability effect in a slot, and, from the map, flyers, neutral units, each enemy ability, bosses and their endings, and optional objectives) to the task or milestone that lifts it, or `null` once it runs; the task that lifts a row sets it to `null`. Every M4 row is lifted; still refused: beams, Unnerved, and `pivot` (M5), spawners (M6), and `layToRest` (M7). `run.checkpoints` refuses nothing and is lifted (T305b emits `CheckpointReached`). Towers registered ahead of their task (`content/towers/index.ts` `TOWERS_AHEAD_OF_TASK`, empty since T408, each with a `tower.<id>` row) stay out of the pools and off the shop's shelves (`stubTowerGate`). `towerRefusal` and `abilityRefusal` answer the same question for one tower or ability, so `meta/pools.ts` keeps a save that runs ahead of the sim (the `all_unlocked` dev save) out of play. Map-script triggers and actions the `triggers` system doesn't run yet are refused separately (`unsupportedScript` in `systems/triggers.ts`).
- **`state`** ([`src/sim/state.ts`](../../src/sim/state.ts)) holds everything that changes: `tick` (ticks completed; during a step, the tick being run, starting at 0), `nextUid`, `outcome`, `credits`, `integrity`, `maxIntegrity` (the run's starting integrity after modifiers, which Results shows the meter against), `wave`, `schedule` (the wave schedule; see *Waves, economy, and the end of a map* above), `scriptFired`, `lockedTowers`, `towerAtTile`, the five pools, the RNG streams, `stats`, `abilityCooldownTicks`, `abilityCooldownWaves` (a cooldown counted in waves: Clearance Sale's), `discountCharges` and `discountPct` (Clearance Sale's purchases left and their saving), `freeCastWave` (Ready Room: the wave whose free cast each slot has used), `wreckage` (the salvage drone's queue, its progress, and the cleared tiles), `holdFireAll` and `spareRunnersAll` (the global toggles new towers inherit), `notFiringAnnounced`, `linksDirty`, `linkPairs` (the active link pairs as `[link, uidA, uidB]` triples, which the links system diffs for its events), `leakAbsorbLeft` (Emergency Bulkhead), `economy` (the run's bounty, early-call, and sell-refund percentages after modifiers, plus the bounty carry), `medals` (each medal `open`, `forfeited`, or `earned`), the `pending` queue, and the output buffers `commandLog` and `events`. Immutable inputs (content, map, config) and per-tick scratch live in the `TickContext` that systems receive, not in state.
- **`hash()`** walks all of `state` generically except the output buffers, so a field added later is covered automatically. Numbers hash by their exact bits; a frozen object with a string `id` (a compiled definition or route) hashes as its id, so two runs over separately compiled but identical content agree. Two lanes (FNV-1a plus a second mix, `src/shared/hash.ts`) give a 64-bit digest. It isn't for hot loops.
- **`runHeadless`** runs one map to the end (or `maxTicks`, default 30 minutes of sim time) with no frame cap, issuing the build's steps through the scripted-build executor ([conventions.md § Balance sims](conventions.md#balance-sims-npm-run-sim)). It takes a ready `SimConfig` and a compiled build (`map.builds.*`, or a policy's); it never imports `meta/`. Its `HeadlessResult` holds the outcome, final integrity and credits, `hash()`, the wave a loss happened in, per-wave tallies (spawned, killed, leaked, integrity lost, the bank as the build phase opened, credits unspent at the wave's start, early-call bonus), per-tower shots and kills, each step's issue tick, lateness and error, and any invariant violations (`headlessTracker.ts` checks them after every tick).
- **`createBuildExecutor`** is the executor on its own: call `beforeTick()` before each `sim.step()`, and it issues whatever steps are due through `enqueue` + `applyPending()`. It never drains events, so a host can drive it alongside rendering: `__sd.autoplay(name)` (`app/autoplay.ts`) runs it from `host.setDriver`, which calls it before every tick of a frame or a `fastForward`.
- **The sim knows nothing about meta progression.** Permanent upgrades, Field Protocols, and difficulty arrive as a list of `Modifier`s. In the game, `app/` gets them from `meta/`. In the harness, `src/balance/profile.ts` composes a map's `referenceProfile` into modifiers through the same pure `meta/modifiers.ts` functions the game uses. For M1, A1M1's profile is empty, so its modifier list is empty.

**Modifiers follow the design's stacking formula** ([design/towers.md §4](../design/towers.md#4-stat-modifiers-and-stacking)): `stat_final = (stat_tier + Σ flat) × (1 + Σ pct)`, with percentages **added, never multiplied**, and per-stat caps on the total percentage.

The union as built, with each kind's documentation and the progression item it serves, is in [`src/sim/config.ts`](../../src/sim/config.ts):

| Kind | Changes | Progression sources (design/progression.md) |
|---|---|---|
| `towerStat` | A tower's (or every tower's) damage, rate, or range | Tune-ups ranks 1 and 3, the Zibzab Tune-up |
| `towerCost` | Build and upgrade costs (`tiers: 'all'`) or tier 4 only (`'spec'`) | Tune-up rank 2, Specialist |
| `enemyStat` | Enemy HP, shields, or speed | Story difficulty, veteran modifiers |
| `economy` | `startCredits`, `coreIntegrity`, `bounty`, `earlyCallBonus`, `salvage`, `clearSpeed`; `set` replaces the map's value first (lowest wins) | Seed Money, Reinforced Core, Bounty Hunter, Salvage Rights, Head Start, Salvage Expert, Early Bird, Bounty Board, Story (`coreIntegrity` set 30) |
| `sellRefund` | Adds to the sell refund fraction (0.7 → 0.75 → 0.8) | Resale Value |
| `abilityStat` | An ability's (or every ability's) cooldown or radius, by ability id | Ability Coolant, Orbital Strike Mk II, Companion Rapport |
| `countdown` | Wave countdown length | Story difficulty, veteran Rush Hour |
| `linkBonus` | Every link's bonus × (1 + pct) | Linked Up |
| `tileBonus` | Adds to a tile's bonus fraction (high ground 0.25 → 0.40) | High Ground Training |
| `leakAbsorb` | Absorbs the first *n* integrity lost to leaks, once per map | Emergency Bulkhead |
| `firstBuildFree` | The first tower each map costs nothing (tier 1) | Rapid Deploy |
| `freeCast` | Each ability's first cast in a given wave starts no cooldown | Ready Room |

`pct` is a fraction (+10% → 0.10). Every kind carries a `source` (`'shop:<id>'`, `'difficulty:story'`, …) for the UI's breakdown.

- **Tower stats** (`towerStat` modifiers and every in-map source) are summed into per-tower scalar slots (`flatDamage`, `flatRate`, `flatRange`, `pctDamage`, `pctRate`, `pctRange`, plus `vsStatusMask` / `vsStatusPct` for a link's conditional damage bonus) by the `links` system, recomputed only when something changes: a tower is built, upgraded, specialized, sold, or jammed, a jam expires, or (later) the lighting changes; never per tick. The sources: static `towerStat` modifiers for that tower or `'*'`; its tile (high ground +25% range, a power node +20% fire rate or, for a support tower with no attack, +20% aura strength; `tileBonus` adds to those fractions); each active link once (`linkBonus` scales every link's flat and percent); and auras, the strongest per aura kind, never the tower's own. The slots don't depend on tier, so an upgrade takes effect at once.
- **The final stat** is `(stat_tier + Σ flat) × (1 + min(Σ pct, cap))`, computed where it's read by the pure functions in `sim/bonuses.ts` (a few multiplies): the towers system for damage, range (a scratch `RangeSpec` for targeting), and the period (the simulated rate `60 / cooldownTicks` takes the bonuses and rounds back to whole ticks, so +10% on a 30-tick Rivet fires every 27), and `towerStats()` for the HUD (tiers 1–3, or tier 4 given the spec). A `vsStatus` bonus joins the damage percent, under the same cap, against an enemy with one of its statuses: checked per hit for hitscan and pulses, and per victim on impact for shells (a shell carries `damage` and `damageVs`, and Cluster Thumper's its bomblets' pair). Caps, aura kinds, tile fractions, and the status bit order are data in `content/rules.ts`, not hard-coded.
- **Costs and the run economy.** `towerCost` applies at purchase (`costFor`: `round(base × (1 + Σ pct))`; `'spec'` modifiers only on tier 4), and `invested` records what was paid. `createSim` applies the rest once (`applyRunModifiers` in `sim/economy.ts`): `startCredits` and `coreIntegrity` as `(set ?? base + Σ flat) × (1 + Σ pct)`, rounded (lowest `set` wins; integrity at least 1, and `state.maxIntegrity` records it); `leakAbsorb` into `state.leakAbsorbLeft`, which `movement` spends before the core loses any (`EnemyLeaked.leak` is what the core lost); and the `bounty`, `earlyCallBonus`, and `sellRefund` numbers into `state.economy`, so the HUD's helpers read the run's numbers. `bounty` and `earlyCallBonus` take `pct` only; a `set` or `flat` on them makes `createSim` throw.
- **Light.** A map's lighting schedule (`MapDef.lighting`, keys of a wave and an env palette) is cosmetic until Sundown: the sim never reads it, and render crossfades the sky and a multiply grade from it (A2M3; [art-direction.md §7](../art/art-direction.md#glow-and-bloom)). **Darkness** that affects play (A2M6 Sundown onward, M5) extends a key with a darkness level the sim derives from the wave, as render does: a range penalty on towers outside every light source. The `setLighting` script action changes the light at a script moment (the finale's Dawn, M7). A tower def's `lightRadiusTiles` (Prism Spire's beam) makes a light source, so nearby towers keep full range. Render draws the same sources as light stamps ([art-direction.md §7](../art/art-direction.md#7-vfx)).

## 3. Content (`src/content/`)

**Content is data**: typed TypeScript files, one entity per file, with explicit registries (no `import.meta.glob`, so the same files load in Vite, Vitest, and plain Node).

- **Ids** are `snake_case` strings, unique per kind. Id union types are derived from the registries (`type TowerId = keyof typeof TOWERS`), so a typo in a wave file is a compile error.
- **Exact numbers live in content files.** Design docs hold intent, roles, and target ranges, and link to the content file rather than copying its numbers.
- TS types check shape at compile time; `validate()` checks what types can't (cross-references, ranges, grid geometry, design rules). No schema library is needed, because content is TS, not JSON. Untrusted input (save import) gets its own validator in `meta/`.

### Data shapes

**The code is the home of the data shapes:** [`src/content/types.ts`](../../src/content/types.ts) defines what content authors write (`TowerDef`, `EnemyDef`, `AbilityDef`, `MapDef` and its parts, waves, builds, conditions, and the map-script triggers and actions), and [`src/content/compiled.ts`](../../src/content/compiled.ts) defines what the sim reads (`CompiledContent`). Design docs link there instead of keeping their own sketches. The essentials:

- **Units are in field names** ([conventions.md § TypeScript style](conventions.md#typescript-style)). Content is authored in seconds and tiles (`ratePerSec`, `rangeTiles`, `flightSec`); compiled data is in ticks and tiles (`cooldownTicks`, `rangeSq`, `speedTilesPerTick`). The tile is the sim's only distance unit; tile `(c, r)` has its center at `(c + 0.5, r + 0.5)` ([art/tech-spec.md § Grid ↔ screen math](../art/tech-spec.md#grid--screen-math)).
- **Id unions come from the registries** (`type TowerId = Extract<keyof typeof TOWERS, string>`). Types that refer to another kind's ids take an id space `K` that defaults to the live registries, so test fixtures (`src/content/__fixtures__/`) get the same typo checking against their own registries. A definition never names its own kind's ids (`MapDef.revisitOf` is a plain string that `validate()` checks), which keeps the types free of cycles. Kinds without a registry yet (upgrades, protocols) are `never`, so nothing can reference them until their task adds one.
- **Towers:** tier 1 is complete; tiers 2 and 3 are patches on the tier before, and the tier-4 specs (optional; a tower without them rejects `specialize` with `noSpecs`) patch tier 3. Targets and default priority live on the tier, so a spec can change them (Railspike's Strong, Cloudburst's air). Attack kinds: `hitscan`, `projectile` (flies to its target at a fixed speed, with an optional burst on arrival, `splashTiles`: Skyhook's flak), `lobbed` (fixed flight time, optional lead, optional `bomblets` scattered on impact: Cluster Thumper), `beam`, `chain` (`jumps` after the first hit, so `jumps + 1` targets), `spawner`, and `pulse` (hits every enemy in range each period, with no target: the Sprinkler's chill aura). Armor pierce and ignore-armor are attack fields on every kind. Towers and enemies carry a display `name` ("Rivet", "Brood Hauler") that every screen shows (T119).
- **Enemy abilities** are optional fields on `EnemyDef`, one per ability: `burrow`, `split` (the enemy it releases and how many), `huddle`, and `boss` (phases by HP share, each with optional `spawn`, `burrow`, `hastePct`, and `huddle`, and the `ending`: `driveOff`, `retreat`, `pivot`, or `layToRest`). `neutral` marks a unit towers target but can't hurt (Gerald).
- **Abilities** have a cooldown in seconds (`cooldownSec`) or in waves (`cooldownWaves`: Clearance Sale), never both. Effect kinds: `strike`, `segment`, `slowAll` (Time Dilation: no target, with a boss rate), and `discount` (Clearance Sale: charges and a fraction off).
- **Optional objectives** (`MapDef.objectives`, `ObjectiveDef`) have an id, a `name` and one-line `description` for the briefing, tracker, and Results, a condition in the medal grammar, their Intel, and optional `onComplete` actions.
- **Waves:** a group's `intervalSec` defaults to the enemy's `spawnIntervalSec` (its data file in [`src/content/enemies/`](../../src/content/enemies/)), and its `route` (a path, air-lane, or rift-lane id) also fixes its spawn. A wave's `countdownSec` defaults by act ([design/core-loop.md §2.1](../design/core-loop.md#21-phases)). Wave tags (`WaveTag`) include `quiet_wave`, `youngling`, and `fleeing`, which allies and the spare-runners filter never pick.
- **A map** is `MapLayoutDef` (`map.ts`) + `WaveDef[]` (`waves.ts`) + `BuildsDef` (`builds.ts`), composed by `defineMap` ([conventions.md § Add a map](conventions.md#add-a-map)).

**Compiling** (`compileContent()` in `src/content/compile.ts`; its header comment is the home of the conversion and merge rules) turns seconds into whole ticks and rates into whole-tick periods, resolves tier patches into full per-tier definitions, gives wave groups direct references to their compiled enemy and route, turns routes into polylines through tile centers with cumulative lengths, compiles `towerUnlockWave` into `{ wave: N, phase: 'countdown' }` → `unlockTowerClass` events (ahead of the authored events) plus the map's `lockedTowersAtStart`, turns build steps into tagged steps, resolves every optional field to a value or `null`, and deep-freezes the result. Anything it can't compile past (an unknown id, a registry key that differs from its id, a malformed tile grid, a route that breaks the route format) is reported with the validation errors in one `ContentCompileError`.

### Validation

`compileContent()` runs `validate()` ([`src/content/validate.ts`](../../src/content/validate.ts)) first and throws one `ContentCompileError` listing every validation and compile problem, so invalid content never compiles; each validation error reads `[rule] where: message`. **The code is the home of the check list:** the headers of `validate.ts`, `validateMap.ts`, and `validateBuilds.ts` name every rule they check, and `validate.test.ts` has one failing fixture per rule. `content.test.ts` validates the live registries (the schema test). The design rules are owned by the linked design docs; their values (caps, the trait → counter-category map, the answer lists, limits) live in `rules.ts`. In summary:

- **References and ranges:** ids exist (compile), sprites are registered and of the right category, numbers are in range on every resolved tier, enemy traits agree with the data and show their tells, and only the listed jammers jam. Sprite grids, master-palette colors, the Hollow hue reservation, and path-vs-pad contrast run through `sprites/validate.ts` and `palettes/validate.ts`.
- **Geometry** ([design/maps.md §9](../design/maps.md#9-map-data-shape-for-implementers)): the route format is a compile error (`compileMap.ts`), and so is an ally post naming an unknown marker. `validate()` adds: every wave group can walk its route, a Defend map has one core, markers (so ally posts) sit on decor, wreckage says what lies under it and pays 30–80 salvage, and `cols + rows ≤ 36` for campaign maps.
- **Waves** (`validateWaves.ts`): every group can walk its route and carries known tags; `[fleeing-lead]`: a fleeing group leads the hushing Hollow group behind it on its route by 2–4 s (D109; a fleeing group with no Hollow behind it is exempt); `[quiet-wave-reach]`: no pad's tier-3 reach covers the Quiet Wave's first tiles ([design/maps.md §9](../design/maps.md#9-map-data-shape-for-implementers)), counting only towers the run that first wins the map can own (D107, D129).
- **Threats** ([design/maps.md §6.2–6.3](../design/maps.md#63-one-new-thing-per-map)): `threatIntel` equals the traits in the waves; `requiredCounters` has at most 3 entries, each with a `noCounterBuilds` entry; soft enemies stay within 15% of every wave's threat; teach waves teach a new trait; in campaign order, at most two new threats and one new required-counter category per map (a capstone boss, whose traits and brood are all known, isn't a new threat).
- **Companions and allies:** each companion a map names `present` (or in its pick list) has an ability whose `companion` field names them, a companion has at most one ability, and a pick list is non-empty with no repeats; ally posts have sane attack numbers, one ally per post, and Bricks at most once.
- **Builds:** loadouts (≤ 4, owned by the reference profile; a build names a companion only from its map's pick list), what each scripted step means on the map (buildable empty tiles, unlocked towers, towers built by then, tiers and specs, a slot-2 cast only with a present companion or a pick), no-counter builds carry no answer to their category and alt builds carry one to every required counter (`content/counterAnswers.ts`, shared with the harness and the loadout screen: the tiers and specs a build's towers reach, **where they stand** (a placed tower answers only if one of its placements reaches a route the category's enemies take), and the abilities it casts; [design/enemies.md §3.1](../design/enemies.md#31-counter-categories)), and from A1M4 there are at least 2 alt builds sharing at most 2 tower types with par.
- **Medals and conditions** (`validateMedals.ts`): every campaign map has a Challenge with a snake_case id that isn't built in, a name and description that fit the briefing, and a condition that never references medal-exempt units; every condition has sane bounds, and a `passedMarker` marker sits within 1.5 tiles of a route its units walk. Each optional objective has a snake_case id, a name and description that fit the tracker, pays at least 1 Intel, never references medal-exempt units, and the campaign's objectives pay at most `OBJECTIVE_INTEL_BUDGET` (7) Intel.
- **Scripts:** wave triggers, markers, objectives, and forced inputs exist; cue ids follow `<map_id>_wNN` or `<map_id>_<slot>` ([story/style-guide.md](../story/style-guide.md)); every flag a script reads has a `flagVariants` entry.
- **Enemy abilities** (`[enemy-ability]`): each ability goes with its trait or tell (burrowing ⇔ `burrow`, splitting ⇔ `split`, huddle ⇔ `huddle`, the `boss` tell ⇔ `boss`); a split or a boss spawn names an existing enemy other than itself; a boss pays no bounty, its phases start at full HP and fall, and it ends below its last phase; a neutral unit leaks and pays 0 and has no trait but flying.
- **Feature guards** (`[feature]`): content that needs a system that doesn't exist yet is refused rather than mis-simulated: objectives other than Defend and Protect (Escort with its safe exits, Holdout, Choir: T305c). Content for a mechanic the sim doesn't run yet (a beam tower, a `pivot` boss) may be registered, and `createSim` refuses it instead (`FEATURE_GATES`, [§ Sim public API](#sim-public-api)).
- **Purchasable profiles** (`validatePurchasable.ts`, `[purchasable]`): every campaign map's reference profile is obtainable and affordable on its own timeline ([design/progression.md §10](../design/progression.md#10-pacing-targets-and-tuning-assumptions)).
- **Revisits** (`[revisit]`, `compileRevisit.ts`, which composes each revisit with its original before validation): the original centred and unchanged, new pads only in the band, no route, marker, or wreckage key twice.
- **Not yet checked** (TODOs in the code, waiting for content that can't exist yet): locked abilities per flag variant (M5). The dialogue rules are in [story-runtime.md § Validation](story-runtime.md#validation).

Its tile lives in `BattleInteraction` (`cursor`, −1 while hidden; `cursorLast`, where it reappears; `cursorNav`, the line its arrows travel), independent of selection, arming, and aiming. The first arrow shows it on the selected tower, else its last tile, else the target nearest the map's middle (`cursorStart`); each later arrow moves it by **the cursor rule** (`input/cursor.ts` `cursorStep`): measure on the screen with vertical pixels counted double (an iso tile step is then the same length whichever way it goes); a target counts as "that way" within 45° of the arrow (so an edge-sharing iso neighbour counts for both arrows it sits between), and anything on that side counts only when nothing is in the cone; the score is the distance along the arrow plus half the distance off the line the cursor started on (kept while the same axis repeats), so repeated presses follow a straight screen line, zig-zagging over its tiles instead of drifting; ties go to the move along a grid axis (Up/Down change the row, Left/Right the column), then to the lower tile index; with nothing that way it stays. ### UI: DOM overlay

**Decision: menus, the HUD, and dialogue are a Preact DOM overlay above the canvas. In-world UI (range rings, health bars, tells, floating numbers, placement ghosts) is drawn in Phaser.**

Why DOM:
- Stardust is **text-heavy** (dialogue, codex, memos, shop). DOM gives us text layout, wrapping, scrolling, and selection for free. Phaser text would need a hand-built layout engine.
- **Accessibility:** focus order, keyboard navigation, screen-reader labels, and user font scaling.
- **Forms:** player name and pronoun entry, and the save export/import text field.
- **Agent-friendly and testable:** Playwright can query DOM elements by role and text, and components are plain TSX.
- **Touch-ready:** native hit testing and scrolling.

How:
- `#ui` is a 640×360 box (in game pixels) layered over the canvas and scaled with CSS **`zoom: var(--ui-scale)`**, the same zoom as the canvas. All UI is authored in game pixels. (Use `zoom`, not `transform: scale`, so text re-rasterizes crisply and pointer coordinates stay correct.) `--ui-scale` is the canvas's CSS zoom, `n / devicePixelRatio` (`cssZoom` in `render/scale.ts`), not the integer `n` itself: one game pixel then covers exactly `n` *device* pixels, so text and icons stay on the device-pixel grid at fractional DPRs (1.25, 1.5) too. `app/boot.ts` sets it on `#ui` on boot and resize. `#ui` also carries the UI act theme as `data-act` (`ui/Overlay.tsx` `uiTheme`; the themes are [art-direction.md §9](../art/art-direction.md#9-ui-style)): a battle's and its Results' are the map's (`presentationOfMap`); the campaign's menus take the next map's (`presentationBetweenMaps` of the frontier), so Act II's colors arrive with A1M5 won; the Title and the intake stay Act I's. The HUD, Results, and the star map set their own `data-act`, which wins inside them.
- The root has `pointer-events: none`; panels set `pointer-events: auto`, so clicks on empty space reach the canvas.
- **Screens:** `ui/Overlay.tsx` picks the screen from the `screen` signal: `screens/Title.tsx`, `screens/Campaign.tsx` (the Shift board) or, once A1M5 is won, `screens/StarMap.tsx` (the star map), `screens/Base.tsx`, `screens/Settings.tsx`, the HUD (`hud/`) during a battle, or `screens/Results.tsx`. The screens' view models are `ui/screens/state.ts` (`runResult`, the last finished run; `slots` and `campaign`, written by `app/save.ts`); their styles are `ui/screens/screens.css` (Results' own are `results.css`). ### Audio (`src/audio/`, M2+)

Procedural chiptune SFX and layered music on WebAudio (D001 #9, T205). Every sound and every piece of music is **data**; the synth plays any of it the same way. It never blocks the sim and never touches the sim's RNG.

- **Data.** A sound effect is a recipe (`audio/sfx/*.ts`, registry `sfx/index.ts`): up to 4 tone layers (square, triangle, sawtooth, sine, 25% and 12.5% pulse, or filtered noise), each with an ADSR envelope, an optional glide, arpeggio steps, vibrato, and a filter; plus the recipe's gain, priority (0–3), rate limit (`minGapMs`), voice cap (`maxVoices`), cosmetic pitch `jitter`, and an optional music `duck` level. Music is songs (`audio/music/`): tracks of pattern strings (`C4 - . E4`, drum letters `k s h o`, bars split by `|`) on instruments (`music/instruments.ts`), each track on a layer: `base`, `drums`, or `lead`. Looping themes are `title`, `act1_battle`, and `act2_battle` (`music/act2.ts`: the couplet over borrowed minor chords, C | F | Fm | G | C | A♭ | Fm | G at 132 BPM, ending each loop on the leading tone); one-shot cues are the wave-clear stings (`bright_sting`, `bright_minor`, `minor_sting`), `win`, `lose`, and the boss stings (`boss_sting`, `witch_sting`). Act II's sounds live in `sfx/aelari.ts` (glass: a `glass` instrument's inharmonic partial is their timbre in music too), `sfx/hollow.ts`, and `sfx/act2.ts`. `audio/recipes.ts` and `music/pattern.ts` validate it all, and the unit tests run them on every recipe, instrument, and song.
- **Which sound plays** is the pure `audio/eventSounds.ts`, reading the data tables in `audio/eventTables.ts`: tables keyed by attack kind (`ATTACK_SOUNDS`: hitscan → `rivet_shot`, lobbed → `thumper_launch` then `thumper_impact` when that shell's `ProjectileHit` arrives, pulse → `sprinkler_pulse`, projectile → the Skyhook's `flak_fire` then `flak_burst` as the flak bursts, chain → the Zapcoil's `zap_arc`, charge → the Capacitor Bank's `capacitor_discharge` (a crack, an arc, and a thump; its charge hums up to it, below); a shot whose projectile sprite has a row in `PROJECTILE_SOUNDS` plays that instead (the Seeker Swarm's `seeker_launch`, whose 400 ms gap and single voice make a volley of four one launch, landing as `flak_burst`); a Cluster Thumper's bomblets, a lobbed shot with no target, are `BOMBLET_SOUNDS`: no launch, and one `bomblet_pop` whose 120 ms gap and single voice merge a scatter into a pop or two), by enemy (`ENEMY_POP_PITCH` pitches every death sound; a splitter's death adds `split_pop` 40 ms after it, from the battle's compiled defs), by neutral unit (`NEUTRAL_SOUNDS`: Gerald's `gerald_chime` on `NeutralHit`, `gerald_whistle` on `NeutralExited`), by boss (`BOSS_SOUNDS`: its arrival on `BossPhase` 1, a sound on each later phase, and on `BossEnded` its retreat and its `endCue`. Chitterbloom: `boss_arrive`'s comic tuba, `boss_phase`, the `boss_retreat` scurry, and `boss_sting`, "Everglow Bright" as a brass fanfare that stops a step short of home. The Glass Witch: `witch_arrive`'s glass chord in A minor, its top note a hair flat (the cut thread), `witch_phase`'s glass crack, `witch_retreat`'s falling glissando, and `witch_sting`, the fanfare climbing into A♭ and stopping on the dominant while glass answers it in minor), by ability (`ABILITY_SOUNDS`: the strike's charge on cast, its beam and boom when the zone lands, in sync with D022's FX; Suppressing Fire's `suppress_burst` rattle on cast, Time Dilation's `dilation_swell` sagging two octaves, Clearance Sale's `sale_kaching` cash register, Scanner Sweep's `scan_ping`, a sonar sweep with two echoes), and by ally kind (`ALLY_SOUNDS`: Bricks's `bricks_ready` as he takes his post, and a chunky `bricks_shot` per `AllyAttacked`, rate-limited), and for fire control (`FIRE_CONTROL_SOUNDS`: `HoldFireChanged` clicks `hold_fire_on` stepping down or `hold_fire_off` stepping up; `SpareRunnersChanged` plays the same clicks 5 semitones higher). A chain attack's hits (its `ProjectileFired`, then one `ProjectileHit` per victim; D076) crackle `zap_jump` per jump after the first, each 45 ms later and 2 semitones higher (capped at 10; `CHAIN_SOUNDS`), so the arc runs audibly down the line, and the recipe's 35 ms gap and 3 voices thin a crowd of Zapcoils. The "wrong tool" plinks (`PLINK_SOUNDS`, design/core-loop.md § 5): a `ProjectileHit` that struck (`hits` > 0) but took no HP plays `invuln_plink` (a boss between phases), unless its own `ShieldHit` follows, whose ripple says it instead (the plink waits for the next event or the frame's end; an Energy hit stripping a shield isn't the wrong tool), else one with `reduced` (armor blunted it, D069) plays `armor_plink`; both are rate-limited (90 and 80 ms gaps, 2 voices). `WreckageCleared` plays `drone_cleared`. M2's moments have their own sounds (D059): `LinkFormed` rings `link_chime` (two bright notes a fourth apart), `TowerSpecialized` plays `specialize` (a thunk, then a rising sweep with a shimmer), and a `MedalProgress` forfeit plays `medal_forfeit` (a soft, kind falling third, never a buzzer) at the end of its frame, at most once per frame and only mid-run: never in or after the frame of `MapWon` or `MapLost`, whose cue stands alone (D061). The binder subscribes to exactly the event types that can sound (`SOUND_EVENT_TYPES`, from an exhaustive per-type table, so a new event type must be sorted there). `suppress_burst` is 10 dB louder than T207b's and `sack_pop` 4 dB. Builds, upgrades (pitched up a step per tier), sells, unlocks, deaths, leaks, wave starts (an early call plays `wave_call` first), and the end of a map map to sounds or cues. The wave-clear cue comes from `WAVE_CLEAR_CUE` by the map's `jingle` dial (`bright_sting`; Act II's `bright_minor`, then `minor_sting` from A2M4; never the bright sting after Act I, D126; none in Act III) and is held to the end of the frame, so the last wave's clear gives way to the win jingle.
- **Act II's sounds** (T450; tables in `audio/eventTablesAct2.ts`, read the same way). **Deaths by faction** (design/enemies.md § 8): a Skitterkin's by the map's `skitterkinDeath` dial (`SKITTERKIN_DEATH_SOUNDS`: Act I's confetti `enemy_pop`; Act II's `sad_squeak`, a muffled pop and a small squeak falling away, quieter; Act III's still body and the finale's none silent), the Aelari's `aelari_shatter` (a crack and three falling glass notes) and the Hollow's `hollow_unravel` (a faint hiss swelling backwards, cut dead) whatever the dial (`FACTION_DEATH_SOUNDS`; Act III's Hollow die with no sound, enemies.md § 8, which waits for M6's maps). **The Aelari** (`SHIELD_SOUNDS`, `PULSE_SOUNDS`, `BLINK_SOUNDS`): `ShieldHit` ripples `shield_ripple` (a small glass tink, rate-limited) or, `broken`, shatters `shield_shatter`; `ShieldPulse` swells `pulse_tell` through its tell, rings `pulse_fire` as it fires, and an `interrupted` tell plays `tell_fizzle`, as does `BlinkInterrupted`, so Stasis's answer always sounds the same; `BlinkTell` tunes `blink_tell` up a fifth and `Blinked` zips `blink`. **The hush** (`HUSH_SOUNDS`): `HushStarted` draws `hush_tell`'s breath in, `Hushed` cuts the runner's squeak off with a low thud (`hushed`, ducking the music), `SkittishBolt` squeaks `panic_squeak` (one voice; a bolting group is one squeak); `TurnedHeavy` is silent. **The Hollow's quiet** (`HOLLOW_QUIET`): a sound of priority ≤ 1 that an event places (a shot at its tower, a hit, plink or death where it lands, a sack, a ripple, a frost burst) within 1.5 tiles of a live Hollow unit, as the last frame left them (`fieldSounds.quietAt`), is dropped, except the Hollow's own `hollow_unravel`; alarms, speech, and moments (priority ≥ 2) always play. **The rest:** `PulseBurst` (Flash Freeze) blows `frost_burst`, then `stasis_lock` 50 ms later when it froze anything (`STASIS_SOUNDS`); `Revealed` pings `reveal_ping` (one voice: a Scanner Sweep's reveals are one ping), `Cloaked` is silent; `AssetHit` clangs `asset_hit` (priority 3, under the core's leak alarm; `AssetLost` leaves the loss cue alone); `CheckpointReached` plays `checkpoint`, a soft two-note "saved".
- **Field sounds** (`audio/fieldSounds.ts`, pure): what no event announces, read from the sim's public state after each frame, on sim ticks (so a paused battle is quiet): a unit digging in or surfacing (`burrowed` flips: `burrow_dig`, `burrow_surface`); a boss's spawn tell as its last 1.5 s starts (`sneeze_tell` for Chitterbloom, mirroring the sim's `bossTelling`) and the sneeze itself as the tell runs out in the same phase (`sneeze`; a phase change mid-tell cancels it); `huddle_coo` the first time each huddle leader gathers young; a looping enemy sound while that enemy is on the field, one voice however many (`ENEMY_LOOPS`: a Puffwing flock's `wing_flap` every 0.45 s; an Aelari formation's faint glass `aelari_hum` every 1.8 s; and the Hollow humming the jingle wrong, `hollow_hum` every 9 s: G–C–E then C–D–F, F–D–C backwards, every note 20–45 cents off, two voices beating against each other and an octave partial a few cents sharp, so laptop speakers that can't play its G3 still carry the tune); where the live Hollow units stand (for their quiet) and whether any walks (`hollowLive`: the music's steady Hollow duck, below); a hidden cloaked unit's muffled `cloak_steps` every 0.55 s while any walks (`CLOAK_SOUNDS`, mirroring the sim's `cloakedOut`); a charge attack's `capacitor_hum` as its charge starts and at each quarter, 3 semitones higher each time (`CHARGE_SOUNDS`, against the sim's `bonusChargeTicks`); and the salvage drone (`DRONE_SOUNDS`): `drone_fly` as a new tile heads the queue, pitched down as it flies home, and `drone_work` every 0.75 s once the first quarter of the tile's clear time (its flight; render's `droneFlight.ts`) has passed.
- **Speech** (`audio/speech.ts`, recipes in `audio/sfx/blips.ts`; `SPEECH_SFX` is the blips and the tick): each line starts with its speaker's blip, the `blip.<speaker>` named in `content/dialogue/speakers.ts` (14 voices from story/characters.md: QUILL's two bright chirps, Bricks's low "hm", Goldie's lilt, Kip's cocky slide and pin "ding", Sterling's sparkly major "ding-ding-ding", Zibzab's nasal buzz and coin, Ves'thara's struck glass and fifth with a loose strand 11 cents flat beating under it (the cut thread), Pebble's small "eep!" and falling chirp (kin to the Peeker's `peeker_squeak`: she was the Peeker), Thrum's slow hum, Bramble's "hmph" between chitters, Prim's two flat beeps, Gerald's delivery chime, the PA's G–C–E, and the Technician's even "mm-hm"; comms voices open with a radio squelch); `kfa`, `hollow`, `narrator`, and `system` type silently. **Every blip speaks at one level** (D134): its loudest 50 ms sits at about −17.5 dBFS RMS before the limiter at default volumes (within 0.6 dB of each other), loud enough to clear the ducked storms (below). The typewriter ticks `type_tick` (a 30 ms click) per character, pitched per speaker (`TYPE_TICK_PITCH`, an octave up for Pebble, an octave down for Bramble), at most once per 55 ms (about every other character at 40 a second) and not in the 160 ms after the line's blip.
- **The music director** (`audio/director.ts`, pure) picks the theme and layer levels: the title theme on the title, nothing on Results (its cue plays alone), and in a battle the act's theme (`BATTLE_THEME`) with the base always, drums while enemies are on the field or spawning, and the lead for the final two waves or at integrity 5 or less. Paused, the music plays at half level; a finished map fades it out. It also decides the countdown ticks (each of the last 3 s, the last a fifth higher) and the low-integrity klaxon (once as integrity crosses 5).
- **The synth** (`audio/synth.ts`) builds the voices and the bus graph: speech's own sounds (`SPEECH_SFX`) and the alarms (priority 3) → `sfx`, and every other sound effect (priority ≤ 2, `UNDER_SPEECH_MAX_PRIORITY`: the rattle of shots, hits and pops, and the moments, the Hollow's hum, a horn, a chime) → `underSpeech` → `sfx`; theme notes → per-layer gains → a theme fade (crossfades of 0.5 s; layers fade over 0.35 s) → `duck` → `music`; cues → `cues` → `music` (not ducked) → `master` → a glue compressor → a limiter (−8 dB, 20:1) → a trim → a soft clipper → out. A WebAudio compressor adds its own makeup gain ((1 / full range gain)^0.6, +4.6 dB for the limiter), so the trim (`LIMITER_TRIM_DB`, −2.3 dB) keeps only what the old −4 dB limiter added: sounds under the threshold play as loud as before, and the loud ceiling sits about 4 dB under full scale (T323). Fixed trims sit under the player's volumes (`SFX_TRIM` 0.7, `MUSIC_TRIM` 0.32). The pure **voice book** (`audio/voices.ts`) admits each sound effect: its rate limit, its voice cap (the oldest makes way), and a global cap of 16 instances that steals the oldest voice of the lowest priority no higher than the new one, so a Rivet stream is a rattle and pops never drown an alarm. **Dialogue is never buried** (R10, D134): every speaker blip is priority 3 and the typewriter's tick 2, so combat can't steal them, and while a line is spoken (`speaking`) the `underSpeech` bus holds at 0.5 (−6 dB, `SPEECH_SFX_DUCK`, `holdSfxDuck('speech')`) and the music at 0.55 (`RADIO_DUCK`); alarms keep their level. Music is scheduled 150 ms ahead of the audio clock by a 25 ms timer; late notes are dropped, not burst. The music ducks to the lowest active level: 0.55 while a line shows, 0.63 (about −4 dB, `HOLLOW_DUCK` in `eventTablesAct2.ts`) for as long as any Hollow unit walks, and each big sound's `duck` while it rings. Ducks snap down in 30 ms and come back over 200 ms (time constants), except the Hollow's, which eases down and back over 0.4 s (`holdDuck`'s `fadeSec`): one long held breath, never a dip per hum.
- **The engine** (`audio/engine.ts`) creates the `AudioContext` lazily on the first user gesture (pointer or key), remembers the music until then, suspends while the tab is hidden, and is a silent no-op without WebAudio.
- **The binding** is `app/audio.ts`: `installAudio` at boot (the gesture unlock, the UI click and hover sounds on enabled buttons, the rejection buzz on every HUD notice, the speaker's blip as each spoken line starts, the typewriter's tick through `setTypeTick` in `ui/dialogue/LineText.tsx`, the screen's music, and the settings' volumes) and `bindBattleAudio(host)` per battle (drained events through `eventSounds`, with the map's presentation dials, the content's factions, and the field's Hollow quiet; then after each frame the field sounds, the Hollow's duck (held while `hollowLive`, released when the battle unbinds), the zone landings, the Tidybots' chimes, countdown ticks, the integrity alarm, and the director's music). **The Tidybots' chime** (`tidybot_chime`, a cheerful "ding-dong", the same in every act it flies in) rings as each drone's chime frame starts: `app/tidybotChimes.ts` keeps render's books from the same events (a speck per Skitterkin death, up to the pool's 48; a sweep as each wave but the last resolves, unless one is under way) and times each drone from render's own `planSweep` and `tidyTicks`, which depend only on the speck count; each drone of a sweep chimes 3 semitones above the one before, and the map's end drops chimes still to come. `?test=1` keeps audio off (no `AudioContext`); `&audio=1` turns it on.
- **Settings and keys.** `app/settings.ts` holds the volumes (master 0.8, music 0.7, sfx 0.8) and mute, saved under `stardust:settings` ([meta-runtime.md § Save system](meta-runtime.md#save-system)) behind a try/catch, so blocked storage just keeps the defaults. **M** mutes on every screen (`GLOBAL_BINDINGS` in `app/keys.ts`), as does the 16×16 speaker button at the HUD's top right and the title's corner (`ui/hud/MuteButton.tsx`, `aria-pressed` while muted). The volume sliders are on the Settings screen. The menus over the backdrop (Shift board, Base, Settings) keep the title's music.
- **Levels are checked, not heard.** `audio/offline.ts` renders every sound effect, cue, and theme, and two 10 s storms (`STORMS`), through the real graph in an `OfflineAudioContext`, each storm twice: with no ducking (the loudest case), and ducked as the game ducks it (`storm:<id>:ducked`: the offline clock steps every 25 ms like the live pump, so each sound's duck lands with it, the Hollow's duck holds while Hollow walk, and its line holds the radio and speech ducks): `act1`, well past A1M1's W7 at 2× and A1M5's boss wave (every layer up, no ducking, 20 shot attempts, 20 plinks, and 10 pops a second, Thumper fire, flak, a four-jump Zapcoil arc every 0.2 s, a flock, digs, leaks, a strike, Time Dilation and Clearance Sale, every boss sound under the boss sting, Gerald, the drone, and a line typing), and `act2`, A2M2's Witch fight past its worst wave (the Act II theme under `witch_sting`, a shield ripple on every other shot, sad squeaks, shatters and unravels, panic squeaks, two hushes under the Hollow's hum, every Witch sound, Seeker volleys, a Capacitor Bank charging and discharging, Flash Freeze, cloaks and reveals, Scanner Sweep, the rigs hit three times, a checkpoint, Tidybots, and Ves'thara speaking). `smoke/audio.spec.ts` asserts every render is audible, never clipped, and peaks under 0.9 (−0.9 dBFS), every lone sound effect peaks under 0.8 before the limiter, and every storm, unducked or ducked, peaks under −3 dBFS (as built: −4.3 and −4.1 both ways; lone sounds −34 to −5.2, the blips and the strike's boom loudest). **Speech stays on top:** in each ducked storm every speaker's blip, spoken at the line's moment, must stand ≥ 6 dB over the rest of the mix: the blip alone at its loudest 50 ms against everything else over the line's first 0.3 s, both before the limiter (as built: +7.1 to +7.6 dB in the Witch fight, +10.0 to +10.5 in Act I's). It also plays A2M1 by par to W4 and checks Act II's theme, the sad squeak, the Hollow's hum, and the minor-bridges sting (never the bright one). A recipe's own overload check (`recipes.ts`, `MAX_RECIPE_PEAK` 1) sums only the layers that can sound together (`overlapPeak`), so a rattle's separate cracks don't add up.

**"Everglow Bright" variants.** The campaign's motif is one six-note phrase (and its couplet) in seven arrangements ([story/bible.md §8](../story/bible.md#8-recurring-motifs)). As built, the phrase is G–C–E, F–D–C ("Ev-er-glow, Ev-er-glow"), and the couplet answers E–F–G–A–G ("brighter every day") and D–E–D–C ("clearing the way"); both Act I themes carry the couplet as their lead (`music/act1.ts`), and Act II's battle theme carries it bent minor in bars 3 and 6 (`music/act2.ts`). Each arrangement is a named cue in `audio/music/cues.ts`, chosen by the presentation dials or by a script cue, never hard-coded per map (built so far: `bright_sting`, `bright_minor`, `minor_sting`, and `hollow_hum`, which is a sound effect):

|---|---|---|
| `bright_sting` | Upbeat corporate wave-clear sting (the six notes); the full couplet on the PA at shift change | Act I `WaveCleared` |

## 5. Build, test, and deploy

The npm scripts that make up the test loop (D002) are defined here. **What each one checks and how to use them is in [conventions.md § The test loop](conventions.md#the-test-loop).**

| Script | Runs |
|---|---|
| `dev` | `vite`: dev server with HMR |
| `build` | `vite build` to `dist/` |
| `preview` | `vite preview --port 4173 --strictPort`: serves `dist/` |
| `typecheck` | `tsc -p tsconfig.pure.json --noEmit && tsc -p tsconfig.app.json --noEmit && tsc -p tsconfig.node.json --noEmit` |
| `lint` | `oxlint --type-aware && prettier --check .` |
| `format` | `prettier --write .` |
| `format:check` | `prettier --check .` (the formatting half of `lint`) |
| `test` | `vitest run`: unit, sim, content, save, balance-harness, and architecture tests |
| `test:watch` | `vitest` |
| `sim` | `node --experimental-strip-types tools/sim.ts`: headless balance sims for every map, maps in parallel on worker threads (args: `--map <id>`, `--seeds <n>`, `--build <name>`, `--jobs <n>`, `--report`) |
| `smoke` | `playwright test --trace off`: browser smoke tests against `npm run preview` |
| `check:docs` | `node --experimental-strip-types tools/check-docs.ts`: link and docs-index checks |
| `check` | **The whole gate:** `node --experimental-strip-types tools/gate.ts`: `typecheck`, `lint`, `test`, `build`, `sim`, `smoke`, `check:docs` in order, failing fast, then each step's time against its budget ([conventions.md § Gate time](conventions.md#gate-time)) |
| `check:fast` | `typecheck && lint && test` (inner dev loop only, never the gate) |

`package.json` sets `"type": "module"` and `"engines": { "node": ">=22.6" }`.

**Config files:**
- `tsconfig.base.json`: shared strict options.
- `tsconfig.pure.json`: the pure modules, no DOM lib.
- `tsconfig.app.json`: the browser modules, with the DOM lib and Preact JSX (`"jsx": "react-jsx"`, `"jsxImportSource": "preact"`).
- `tsconfig.node.json`: Node-side code with `"types": ["node"]`: `tools/`, `smoke/`, `vite.config.ts`, `playwright.config.ts`, and `src/shared/architecture.test.ts` (it reads files with `node:fs`).
- `tsconfig.json`: a solution-style root (`"files": []` plus references to the three projects) for editors and oxlint's type-aware mode. `typecheck` runs the three projects directly.
- `vite.config.ts` (with `base: './'` so the build works from any subpath, JSX through Vite's `oxc` option with `importSource: 'preact'`, and Vitest config inline), `playwright.config.ts`, `.oxlintrc.json`, `.prettierrc.json` (with `.prettierignore`: Markdown is hand-formatted and not run through Prettier), `.editorconfig`.
- **Playwright's browser:** `playwright.config.ts` launches `CHROME_PATH` when it's set (Claude Code cloud sessions, where the preinstalled Chromium doesn't match the pinned Playwright's revision, so never run `playwright install` there), and otherwise Playwright's own Chromium (CI installs it). It passes `--use-angle=swiftshader --enable-unsafe-swiftshader` so headless WebGL always uses SwiftShader. Smoke runs always pass `--trace off`.

**Imports use relative paths with explicit `.ts` extensions** (`allowImportingTsExtensions`), and there are no path aliases. That lets the pure modules run unchanged in Vite, Vitest, and plain Node (`tools/sim.ts`), with no loader or alias config to keep in sync.

**Bundle:** Phaser goes in its own vendor chunk. Budgets: initial JS ≤ 1 MB gzipped, boot (compile content and bake sprites) ≤ 300 ms on a mid-range laptop.

### Deploy to GitHub Pages (once a remote exists, D001 #10)

1. Add `.github/workflows/deploy.yml`, triggered on push of tags `m*` (and manual dispatch): `npm ci`, `npx playwright install --with-deps chromium`, `npm run check`, then `actions/upload-pages-artifact` with `dist/` and `actions/deploy-pages`.
2. Enable Pages with source "GitHub Actions". With `base: './'` the site works at `https://<user>.github.io/stardust/` without config changes.
3. Saves are per-origin localStorage, so moving the host later orphans saves unless players use export/import. Document that in the release notes when it happens.
