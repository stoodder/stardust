# Story Runtime

How the story runs in code: map scripts (story moments that change play, inside the sim), and `src/story/` (dialogue, conditions, flags, text tokens, barks, and the other story systems). The module layout and the sim are in [architecture.md](architecture.md); content data shapes are in [`src/content/types.ts`](../../src/content/types.ts) ([architecture.md § Data shapes](architecture.md#data-shapes)). Saves and the meta-side story transactions are in [meta-runtime.md](meta-runtime.md).

The authoring format and voice rules are owned by [story/style-guide.md](../story/style-guide.md); the TS types in `content/dialogue/types.ts` must map one-to-one onto its §5. The design homes for the systems below are in [design/core-loop.md §6](../design/core-loop.md#6-story-facing-systems).

**Not in M1.** M1 uses only the `unlockTowerClass` action (compiled from `towerUnlockWave`); A1M1's briefing is static text ([architecture.md, M1 subset](architecture.md#architecture)).

**Built so far.** The flag registry, its run-end rules, and `scriptFlags` from the save ([§ Flags](#flags), T206b). The M3 seams (T300b): the dialogue, codex, and memo data shapes and their registries, the speaker registry, and the profile data. The pure story runtime (T302a): the runner, conditions, text tokens, bark selection, name tags, the counter's presentation, and dialogue validation, each below. The dialogue in play (T302b): the comms panel, scenes that hold input, the briefing as a scene, barks wired to the battle, and the reply button ([§ Dialogue in play](#dialogue-in-play)). The dialogue content (T302c and the map tasks): A1M1's and A1M2's briefings, radio, barks, name tag, and debriefs are dialogue, verbatim from act1.md (`tools/dialogueCanon.test.ts`). The codex and the Everglow Inbox (T303): their logic, Act I's entries and memos, delivery at run end and on entering the base, and the base's Inbox and Codex tabs ([§ Other story systems](#other-story-systems)); codex annotations wait for M4 (D064).

## Map scripts (story-driven sim changes)

Story moments that change play run **inside the sim** as map data, so headless runs, replays, and the balance harness see exactly what a player sees ([design/maps.md §5.3](../design/maps.md#53-map-scripts)). The `triggers` system ([architecture.md § Entity model](architecture.md#entity-model-typed-pools-not-an-ecs)) evaluates them. Dialogue stays in `story/`; the sim only emits `ScriptCue` ids.

The types are `ScriptedEvent`, `ScriptTrigger`, and `ScriptAction` in [`src/content/types.ts`](../../src/content/types.ts), each trigger and action documented there. An event fires at most once per run unless it sets `once: false`. A trigger `{ wave, phase: 'countdown' }` fires as that wave's build-phase countdown begins (W1's is the pre-game build phase). An action `{ cue }` is a scene or bark id that story plays; `revokeAbility` serves A3M2's Orbital Strike and, under C4 Keep, the finale's Time Dilation for Phase 2; `setObjective` is the A2M5 pivot; `setLighting` sets darkness in the sim for render to read; `checkpoint` marks the finale's Phase 2 start ([architecture.md § Checkpoints](architecture.md#checkpoints)); `openTile` targets a predefined decor marker; and `endMap` ends a Holdout as `'completed'`. Revocation, forced input, and clickable objects are described below.

`towerUnlockWave: { [towerId]: N }` in map data compiles to `{ on: { wave: N, phase: 'countdown' }, actions: [{ unlockTowerClass: towerId }] }` (A1M1: `{ thumper: 3 }`).

- **Cue ids** follow `<map_id>_wNN` for wave-bound cues (`a1_m01_w03`), and the other `<map_id>_<slot>` forms from [story/style-guide.md](../story/style-guide.md) for the rest. Validation checks the pattern.
- **`when`** is judged once, on the tick its event's trigger is reached ([§ Conditions](#conditions)). If it doesn't hold then, the event is spent without running; it never waits for the condition to come true.
- **Flags in the sim.** `SimConfig.scriptFlags` carries the story flags a map's scripts and setup may read (`ScriptFlagId`: the registry's flags marked `script: true`, now `door_choice`, `spared_quiet_wave`, `stardust_choice`, `quill_choice`), copied from the save by `app/battleSetup.ts` with `scriptFlagsOf` (only flags that are set; defaults never reach the sim). `ConditionDef` tests them with `{ flag, eq }` ([`src/content/types.ts`](../../src/content/types.ts)). The sim never sets flags; story derives flags from `state.stats` when the run ends ([§ Flags](#flags)). C4's in-play effects are flag-conditioned map data (events, modifiers, and `lockedAbilities`); the rules are in [design/core-loop.md](../design/core-loop.md) §6.11.
- **Forced input.** `forceInput` sets `state.pendingInput`. While it is set, the wave schedule, movement, firing, cooldowns, and timers are frozen. The sim still ticks (so render can animate and `tick` stays monotonic), and `applyCommands` accepts only `{ type: 'scriptInput', id }`. The host shows the single-button overlay on `ForcedInputRequested`. Real-time lines (Bricks's line after 20 s on the SEAL) are a story-side timer on wall-clock time, not sim ticks. The balance harness presses it with a `scriptInput` build step.
- **Clickable world objects.** `setClickable` marks a marker (for example `peeker` in A2M3) as clickable and emits `ClickableChanged`; render highlights it ([art-direction.md §6](../art/art-direction.md#6-story-and-world-sprites)). An `interact` command (valid only while the marker is clickable), or the `fallback` trigger if the player never clicks, fires the `interacted` trigger once and emits `Interacted { by }`. Pebble's A2M3 rescue is built this way, with "W6 cleared" as its fallback. Clicks that change nothing in the sim (poking the Peeker in Act I) are UI events instead (`peeker_poked`, [§ Flags](#flags)).
- **Revocation** selects the class deterministically (most credits invested, then most towers placed, then loadout slot; [design/towers.md §9](../design/towers.md#9-rules-for-story-driven-tower-changes)), sells every tower of it at 100%, adds it to `state.revoked`, and emits `TowerClassRevoked`. Meta copies `revoked` into the save at run end.
- **Rest and scatter** (finale, [design/maps.md §5.5](../design/maps.md#55-the-leaving-song-finale-rules)): when a Hollow unit dies, `cleanup` checks it against every active song zone (squared distance). Inside: `EnemyLaidToRest`, `restPoints += restValue × songMult`. Outside, and if the map's song is active and the unit hasn't re-formed before: it becomes a `reforming` enemy (untargetable, drifting back along its route) and returns at 50% HP after the delay. The song's passive trickle adds rest points every tick. The modifiers by flag come from `MapDef.song`.
- **Bricks in A3M3.** His health bar follows `allies[].healthTimeline` (per-wave percentages in map data), so it drains on a scripted schedule whatever the player builds, and reaches its floor near the end. Results-screen medal toasts are held on that map (a presentation override), so the SEAL plays the same at any score.

## Dialogue runner

A pure state machine over dialogue data (`src/story/runner.ts`): `start(scene, ctx) → cursor` and `advance(scene, cursor, ctx, choiceIndex?)`. A cursor rests on a line, a choice, or the end; `branch` and `set` nodes run on the way, and the effects (flags set, the callsign) ride on the cursor for meta to save when the scene ends (with the scene id in `story.seen`).
- **Choices:** `advance` at a choice needs a valid option index (it throws otherwise). The option's `set` flags join the effects, and a branch later in the scene sees them (the save's flags with the scene's laid over). The cursor's `chose` is the option just taken, so the UI can show its "{Speaker} will remember that." (`remember`).
- **The end:** an `end` node, or falling off the last node. `advance` at the end returns the same cursor.
- **Resuming:** a cursor is plain data. A saved `index` and `effects` resume with `resume(scene, index, effects, ctx)`.
- **Gates:** `scenePlays(scene, ctx)` judges a scene's `when` as its trigger fires; `start` doesn't check it.
- **Bark buttons:** `pressButton(button)` gives the flags to set and the reply scene to play.
- **Read-through:** `linesUntilChoice(scene, ctx)` lists the lines a scene plays with nobody advancing it, up to its first choice or its end (the results card's debrief).
- **Loops:** a chain of branch and set nodes longer than the scene throws (validation refuses such loops first).

**The data shapes** are [`src/content/dialogue/types.ts`](../../src/content/dialogue/types.ts), one-to-one with [style-guide §5](../story/style-guide.md#5-dialogue-format-conventions): `Scene` (an id and its nodes, with an optional `when`), the node kinds `line` (speaker, expression, text, `durationSec`, an optional reply `button`), `choice` (2–3 options, each with `text`, `tone`, the flags it `set`s, `goto`, and `remember`), `branch` (`cond`, `goto`, `else`; `goto`, not `then`, because lint refuses thenable object literals), `set` (a flag and one of its declared values, or the callsign), and `end`; `Bark`, `BarkTrigger`, `Condition`, and the token and glyph ids. The types make a bad speaker, a bad expression for a speaker, or a flag value outside its declaration a compile error.
- **Labels.** Any node may carry a `label`; `goto` and `else` name a label in the same scene. A choice option without `goto`, and a branch without `else`, continue with the next node.
- **Files.** Each map's scenes and map-scoped barks are `content/dialogue/a<act>/<map_id>/scenes.ts` and `barks.ts`, listed once in `content/dialogue/index.ts` (`MAP_DIALOGUE`, with `SCENES` and `BARKS` by id). Barks that can fire on several maps go in `content/dialogue/barks/<trigger>.ts` (`SHARED_BARKS`), each gated by its `when`.
- **What plays a scene** is its id's slot (`<map_id>_<slot>`, [style-guide §5.3](../story/style-guide.md#53-ids); `sceneSlot(id)` parses it, `parseSceneId` in `content/dialogue/rules.ts`): `brief` (the briefing), `w<NN>` (the radio as wave NN's countdown begins), `cue_<name>` (a map script `{ cue }` with the scene's id, or one of the moments app/dialogue.ts plays by name: `cue_name_tag` at Bricks's tag moment, `cue_issued_<tower>` for a newly issued tower at the battle's start; [§ Dialogue in play](#dialogue-in-play)), `debrief` (on the results card), `scene_<name>` (a full-screen scene the flow or a cue plays), and `base_<name>` (a base conversation topic, played as a panel over the base by `app/baseScenes.ts`: A1M3's `arrival` on the first visit with the shop open, while dialogue is on, and its `stardust`, the early ask, from the shop's open-question row).
- **Speakers** are the ids in [style-guide §5.1](../story/style-guide.md#51-speaker-ids), registered in [`content/dialogue/speakers.ts`](../../src/content/dialogue/speakers.ts) with the name plate, its color, the typewriter's blip (`blip.<speaker>`, authored by audio), the frame (`portrait`; `icon` for Gerald; and for portrait-less speakers their text style: `pa`, `form` for `kfa`, `distorted` for `hollow`, `caption` for `narrator`, `ui` for `system`), and the portrait sprite.
- **Portraits** are one sprite per speaker, `portrait.<speaker>` (`src/content/sprites/portraits/`). Its frames are `[<variant>.]<expression>[_talk]` (`neutral`, `neutral_talk`, `party_hat.policy`), with QUILL's `policy_flash` for the tell; the portrait list is in [art-direction.md § Portrait roster](../art/art-direction.md#portrait-roster).
- **Expressions:** the five base expressions plus per-speaker extras (`EXPRESSION_EXTRAS`: `quill.policy`, `pebble.singing`, each with the base expression art falls back to). A line naming no expression uses `neutral`; speakers with no portrait (and Gerald) take none.
- **Portrait variants** are chosen by rules, not by lines: `speakers.ts` lists, per speaker, `{ variant, when: Condition }` in priority order, and the first that holds wins (for example `vesthara`: `touched_deep` in Act III, `touched` from A2M5; `bricks`: `pebble` from A2M3; `quill`: `purge` under `quill_choice = purge`, `party_hat` on A1M5). The finale's `dawn` and Bricks's `dark` (the derived bake, for an absent speaker) are not rules.
- **Silence:** a `line` with `text: ''` shows the speaker's frame (dark for Bricks after A3M3) for `durationSec`, with no text and no typing sound.

## Conditions

Story conditions are data, not strings (`Condition` in [`content/dialogue/types.ts`](../../src/content/dialogue/types.ts), evaluated by `evaluateCondition` in `story/conditions.ts` over a `StoryContext`: the flags, the map the story is about, the lifetime counter, the save's `story.seen`, and the run that just ended):
- `{ flag, eq }`: the flag's value, or its default while unset.
- `{ act }`, `{ mapAtLeast }`, `{ mapIs }`: campaign map ids, built or not, in `content/campaign.ts` order. Before A1M1 (the intake, `map` null) the act is 1 and no map test holds.
- `{ stat: 'pestsProcessed', gte }`.
- `{ seen: <scene or bark id> }`: the id is in `story.seen` (scenes played, once-per-campaign barks).
- `{ all: [...] }`, `{ any: [...] }`, `{ not: … }`.
- Two that read the run that just ended, so they hold only in a debrief, on Results, and in run-end barks: `{ outcome: 'won' | 'lost' }` and `{ thisRun: <boolean flag>, eq }`. `thisRun` is the value that flag's run-end rule gives over this run, set or not; C1's lines read *this run*, its payoffs the flag. Without a run both are false, and so is `thisRun` when the ended map has no rule for that flag. `runContextOf(map, outcome, stats)` builds the run context from the map's rules.

**In-map conditions** (the Challenge medal, optional objectives, and script `when` guards) use the sim's `ConditionDef` ([`src/content/types.ts`](../../src/content/types.ts)), evaluated by `src/sim/conditions.ts` over run state. Its atoms, by when they are judged ([design/progression.md §3](../design/progression.md#3-medals-and-intel), "Evaluation"):

| Atom | Reads | Judged |
|---|---|---|
| `{ towers: { tower?, faction? }, gte?, lte? }` | Live towers of that tower id or faction (all towers if neither) | As things stand (a medal's on the win tick) |
| `{ linkActive: LinkId }` | At least one pair of that synergy link is active | As things stand |
| `{ tagRatio: { tag, of: 'leaked' \| 'killed', gte } }` | That tag's leaked or killed units ÷ its spawned units (false when none spawned) | As things stand |
| `{ stat: RunStat, gte?, lte? }` | A run counter (`integrityLost`, `towersBuilt`, `creditsSpent`, `abilityUses`); counters only grow | Over the run |
| `{ passedMarker: { marker, enemy? } }` | A unit of `enemy` (any enemy if omitted) went past the marker at some point: its route distance passed the route point closest to the marker (the later one where a route doubles back). Medal-exempt units never count. Latched each tick in `stats.markersPassed` | Over the run |
| `{ flag, eq }` | `SimConfig.scriptFlags`; an unset flag never matches | Fixed for the run |
| `{ all }`, `{ any }`, `{ not }` | Combinators | — |

A condition **settles** once the rest of the run can't change it (`settledCondition`): a flag at once, a `stat` past its `lte` (false) or at its `gte` with no `lte` (true), a `passedMarker` once passed (true), and the combinators by three-valued logic. State atoms stay open until judged. That is how a Challenge such as A1M2's "no Brood Hauler gets past the pump station" (`{ not: { passedMarker: { marker: 'pump_station', enemy: 'hauler' } } }`) is forfeited the moment one does ([architecture.md § Medals](architecture.md#medals)). The validator's rules for conditions and medals are in [`src/content/validateMedals.ts`](../../src/content/validateMedals.ts).

## Flags

Flags are declared in `content/dialogue/flags.ts` (`FLAGS`): each with its `values` (a boolean flag lists `true` and `false`; a choice lists its ids, such as `'convoy'`, `'warren'`), a `default`, an optional `script: true`, and a one-line description. `FlagId` and `ScriptFlagId` (`content/types.ts`) are derived from it, so a typo'd flag is a compile error, and a map's `flagVariants` may list only that flag's values. The registry is exactly the canonical flag table, [story/campaign.md](../story/campaign.md) §6.2, in its order and with its values (`tools/flagLedger.test.ts` checks it; the bible's table is a summary).

- **Defaults** are what story reads while a flag is unset (`flagValue` in `src/story/flags.ts`): `false` for a boolean (not done yet), `null` for a choice not made yet. The sim never sees a default ([§ Map scripts](#map-scripts-story-driven-sim-changes)).
- **Who sets them:** the intake (`arrival_reason`, T306), `choice`/`set` nodes, UI events (`peeker_poked`, `asked_zibzab_early`, optional bark buttons), or **run-end rules**.
- **`peeker_poked`** (T309) is written the moment the Act I Peeker is first poked (`app/peeker.ts`, through `updateActiveSave`), not at run end: a poke on any Act I map counts whether that run is won, lost, or abandoned, and the run end builds on the same in-memory save, so it keeps the flag. Later pokes write nothing. A battle with no save in play (`?map=`) sets nothing.
- **Saves** hold `story.flags` keyed by `FlagId`, each value one of the flag's declared `values` ([meta-runtime.md § Validation](meta-runtime.md#validation)).

**Run-end rules** (`FLAG_RULES` in `content/dialogue/flags.ts`) derive a boolean flag from the finished run's `state.stats` when a map ends:

```ts
{ flag: 'spared_quiet_wave', onMapEnd: 'a1_m05',
  value: { tagRatio: { tag: 'quiet_wave', of: 'leaked', gte: 0.75 } } },          // design/core-loop.md §2.7
{ flag: 'held_fire_second_look', onMapEnd: 'a2_m03',
  value: { all: [{ tagRatio: { tag: 'fleeing', of: 'leaked', gte: 0.5 } },
                 { stat: 'holdFireUses', gte: 1 }] } },                          // plain Hold Fire only
```

- **The grammar** (`FlagRuleCondition`) is the sim's condition atoms that make sense after a run: `tagRatio` (leaked or killed ÷ spawned for a wave tag; false when none spawned), `stat` over the run counters `holdFireUses`, `holdFireTicks`, `integrityLost`, `towersBuilt`, `creditsSpent`, and `abilityUses` (`gte`/`lte`), and `all`, `any`, `not`. `holdFireUses` counts only plain Hold Fire turned on, never the Spare runners filter ([architecture.md § Commands](architecture.md#commands-input-into-the-sim)).
- **When they apply:** `src/story/flags.ts` `runEndFlags(mapId, stats)` evaluates the rules whose `onMapEnd` is the ended map, and meta's run end applies them only on the run that **first wins** that map ([meta-runtime.md § Run end](meta-runtime.md#run-end), step 2). Each rule sets its flag to `true` or `false`, so the flag is always set once the map is won. Losses and replays never change it: the map's results stamp, its memo, and every later payoff follow the run that completed the map.
- **The harness** judges C1 with the same rule: assertion #16(a)'s held run must make `spared_quiet_wave`'s rule true ([conventions.md § Balance sims](conventions.md#balance-sims-npm-run-sim)).

## Text substitution

`story/text.ts` runs on every line, bark, choice, memo, codex version, tip, results line, and epilogue card:

| Token | Resolves to |
|---|---|
| `{name}` | `profile.name` |
| `{callsign}` | `profile.callsign` (Sprout, Thorn, Waykeeper; `CALLSIGNS`) |
| `{they}` `{them}` `{their}` `{theirs}` `{themself}` and capitalized `{They}` `{Them}` `{Their}` `{Theirs}` `{Themself}` | The forms from `profile.pronouns` (`PRONOUN_SETS` in [`content/dialogue/profile.ts`](../../src/content/dialogue/profile.ts): `she`, `he`, or `they`, each with all five forms and its `agreement`) |
| `{v:<plural>\|<singular>}` | Verb agreement: the first form when `agreement` is `plural` (they/them), the second when `singular` (she, he). Any pair works: `{v:are\|is}`, `{v:were\|was}`, `{v:have\|has}` |
| `{pests_processed}` | The lifetime counter with thousands separators; inside a map it is the save value plus the run's `skitterkinKilled` so far |
| `{evacuated}` | The current map's meter count (Evacuated, Sheltered, or Voices); 0 outside a map |
| `{glyph:<id>}` | An inline glyph from the pixel font's glyph set (`sun`, the Evie sun used in memo sign-offs; `star`, the results-screen ★). Unknown ids fail validation |

**Before the intake** (a profile of null, which a v1 save has until the intake runs on Continue), tokens read `NO_PROFILE`: "Technician", Sprout, and they/them. An unknown or malformed token throws (validation catches it first). `{glyph:…}` resolves to one character for the renderer to draw: `★` for `star`, and the private-use `U+E000` for `sun` (`GLYPH_CHARS`). The token grammar, the worst-case lengths, and the limits live in `content/dialogue/rules.ts`, so validation can read them (content never imports story); `story/text.ts` re-exports `worstCaseLength` and `tokenProblems`.

Emphasis `*word*` (at most one per line) renders italic; parentheticals such as `(hum, six notes)` and `(squeak)` are plain text. Lines from `hollow` render in the `distorted` style (dropped letters and misregistered glyphs, cosmetic RNG, reduced to plain grey text in reduced-motion mode).

## Validation

`content/validateDialogue.ts` (run by `validate.ts`, so by the content test and `compileContent`) enforces the style guide's mechanical rules over every scene, bark, and name tag. Its header lists each rule by name; in short:
- **Lengths after worst-case substitution** ([style-guide §5.4](../story/style-guide.md#54-text-tokens-and-length)): `{name}` counts 16, `{callsign}` 9, `{pests_processed}` 9 ("1,234,567"), `{evacuated}` 5, pronoun tokens their longest form, `{v:…}` its longer form, `{glyph:…}` 1. Limits (`TEXT_LIMITS`): dialogue line 120, bark 80, choice option 60, bark button 16, name tag 16, codex version 600, memo body 600 and small print 140, loading tip 80, shop description 100, epilogue card 240. Scene sizes count the lines of the longest play-through (each branch on its own): briefing ≤ 8 lines, radio slot 1–3, mid-map cue ≤ 4, full-screen scene ≤ 20, debrief ≤ 6, base topic ≤ 8.
- **Ids and references:** every speaker exists; every expression exists for its speaker (none for a speaker without a portrait); tokens parse; scene ids match `<map_id>_<slot>` under their own map; bark ids start with their speaker and (for a map's barks) name its act; ids are unique; a reply button's `reply` and a `seen` condition name registered ids.
- **Protected `{name}`:** it may appear only in scenes and barks for maps at or after `a3_m03` in campaign order (a shared bark's `when` must imply that), in `system` copy (name tags, onboarding), and in epilogue cards, and never in a `sterling` line.
- **QUILL's tell:** a `quill` line uses expression `policy` if and only if its text starts or ends with "(Per policy.)".
- **Exclamation budget:** `bricks` and `vesthara` lines never contain `!`; in Act III scenes only `sterling` and `pebble` lines may; `quill` never does after A3M2; in the finale only `pebble`, `sterling`, and `system` (the final lyric) may. Choice options and button labels count as the player's. A shared bark's act is the one its id names. Softer per-act guidance stays with writers.
- **Shape:** at most one `*emphasis*` per line; a silence line has `durationSec` (and every duration is > 0); a `choice` has 2–3 options; a `remember` appears only on C3 and C4 choices (one setting `door_choice` or `quill_choice`); dialogue never sets a flag a run-end rule owns (so C1 is never a choice); reply buttons ride only on radio and cue lines.
- **Flow:** labels are unique in a scene and every jump names one; every node is reachable from the first; no loop runs through branch and set nodes alone.
- **Conditions and barks:** `thisRun` names a flag with a run-end rule; `outcome` and `thisRun` appear only in debriefs and full-screen scenes; bark trigger waves and phases are positive integers; a `flag` bark has a `when`; `cooldownSec` is > 0 and never set with `once`.
- **Name tags** are on planned maps, in campaign order.

## Barks

Scenes and barks bind to triggers: map script cues (`ScriptCue`), bark-matrix events (the trigger ids and their exact conditions are owned by [design/core-loop.md §6.3](../design/core-loop.md#63-barks); each maps to a sim event or a host event), and menu events (entering the base, the shop, the star map, the Inbox). `story/barks.ts` picks barks by the style guide's priority (script cue → boss → first-time trigger → repeat), spacing (one per 6 s of sim time unless scripted), presence (QUILL and the companion only; QUILL is absent when `quillOffline`), and no-repeat pools, using its own seeded RNG. A bark slot assigned to an absent speaker plays that speaker's authored silence line. The state (`BarkState`, from `newBarkState(seed)`) is plain data the caller keeps per battle:
- **`pickBark(pool, event, state, ctx)`:** an event is a trigger with its parameters, the sim time, and the speakers present. A bark is a candidate when its trigger matches (the same id, and every parameter the bark names equal to the event's), its `when` holds, its speaker is present (or its text is `''`, a silence, which plays for an absent speaker), and it is available. **Available:** a bark with neither `once` nor `cooldownSec` plays once per map; `once: 'campaign'` also skips barks in `story.seen`; a bark with `cooldownSec` repeats once that much sim time has passed. The most specific candidates win (a tagged `tower_sold` over the generic one); among them unplayed ones come first, then a seeded draw. Within 6 s of the last bark nothing plays, and nothing queues.
- **`pickBarkOf(pool, events, state, ctx)`:** the events of one moment, tried in priority order (a boss trigger, or `boss_phase`; then a trigger's first firing this map; then repeats), at most one bark, every event counting as fired.
- **`cueBark(bark, atSec, state)`:** a bark a map script cue names plays regardless of spacing, presence, and once limits, and later barks keep their spacing from it.
- **Never a reply:** a bark is always its own radio batch. The comms panel never shows it under another speaker's line as if it answered it (D061); authored replies are the next line of the same scene, or a button's `reply`.
- After a battle, `campaignBarksPlayed` lists the once-per-campaign barks to add to `story.seen`.

`BarkTrigger` ([`content/dialogue/types.ts`](../../src/content/dialogue/types.ts)) carries core-loop's trigger ids with their parameters (`enemy_killed`, `enemy_leaked`, and `new_enemy` name an enemy; `tower_built` and `tower_sold` may name a tower, and `tower_sold` whether it was tagged; `wave_start` and `wave_cleared` may name a wave or the boss wave; `boss_phase` a phase), plus the Act I radio's event barks that core-loop's table doesn't list yet: `bank_nudge` (D059), `enemy_leaked` (D059), `neutral_hit` (Gerald, A1M3), `tower_issued` (D061), and `menu` (entering a base screen). A bark may play `once` per map or per campaign; the save keeps once-per-campaign barks in `story.seen`.

**Optional bark button.** A bark (or radio line) may carry `button: { label: string; set?: FlagSet[]; reply?: SceneId }`, for example QUILL's Act I knock-knock joke with a "Who's there?" button. The UI rule is owned by [design/core-loop.md §6](../design/core-loop.md#6-story-facing-systems); in code:
- The button shows in the comms panel for the bark's display time and then goes away. It never pauses, never blocks input, and never changes the sim, so it isn't a `Command` and isn't in the command log.
- Pressing it emits the host event `BarkButtonPressed { barkId }`; story applies `set` and plays `reply`. Not pressing it is a valid outcome and needs no default.
- The balance harness ignores bark buttons. The forced single input ([§ Map scripts](#map-scripts-story-driven-sim-changes)) is the blocking counterpart, and the two share a visual grammar ([art-direction.md §9](../art/art-direction.md#dialogue-presentation)).

## Dialogue in play

`app/dialogue.ts` plays scenes and barks over the runner and `story/barks.ts`, and writes the views in `ui/dialogue/state.ts` (`dialogue.comms`, `dialogue.scene`) that `ui/dialogue/` draws ([art-direction.md § Dialogue presentation](../art/art-direction.md#dialogue-presentation)). `bindDialogue(host, { briefing, newTowers })` wires a battle (`app/battle.ts`).

- **Staging** (`sceneMode`): a `brief` scene is the briefing; a `scene_*` is full-screen; any other scene with a `choice` node is a **pausing panel** (a choice can't wait on a panel that never blocks); everything else (`w<NN>`, `cue_*` without a choice, a reply) plays on the **comms panel**.
- **Scenes that hold input** play one at a time (later ones wait their turn). In a battle, every one but the briefing pauses the sim with `setSpeed(0)` and puts back the speed it found as it ends (a pause the player made stays a pause). Game hotkeys are off and the HUD is `inert` while one is open; the comms panel waits, and its queue's staleness clocks restart when it frees. A line types at 40 characters a second; Next (a click on the line or the button, Enter, or Space) finishes the typing, then moves on. The typewriter's clock is the scene's own (`nextScene`), so presses faster than the screen redraws still land one step each. A choice's options are buttons (the first focused; Up and Down move between them); the pick joins the transcript as the player's line, and a C3/C4 option's "{Speaker} will remember that." shows until the next step. Esc skips to the next choice (which still waits) or the end (`skipScene`).
- **The briefing** is the map's `<map>_brief` scene; a map without one has no briefing. It opens as a fresh battle starts (not on Retry) and plays in the briefing modal, the threat intel and medals under it, until Clock in (or Esc). It doesn't pause: the setup phase waits for the player anyway. Once it has played out, Clock in takes the focus. `hud.briefing` holds its id while it's open.
- **The comms panel** plays a scene's lines in order on real-time holds: a line's reading time (4 s, plus 40 ms a character past 60), at least 2.5 s once typed, or its `durationSec`; a line answered by the next (another speaker) holds only until 2.5 s after it's typed, and the answer shows under it with its cue kept above (D028). Scenes queue behind the line on screen; one that waited more than 15 s of real time (`COMMS_STALE_MS`) is dropped. The moments that play scenes: wave NN's countdown (`w<NN>`) and a map script's `ScriptCue` (the scene with the cue's id; a cue naming a bark queues that bark, `cueBark`).
- **Barks** (`offerBarks`): each sim moment is offered as triggers to `pickBarkOf` over the map's pool (`barksFor`), with the battle's `BarkState` and the speakers on the radio (QUILL and a present companion, `presentSpeakers`). A bark is its own one-line scene on the panel, never under another line. Nothing plays while a line is on the panel or a scene holds input, and nothing queues: the triggers still count as fired. **Two triggers queue instead** (`isQueuedTrigger`), because their lines must never be lost: `first_leak` (QUILL's "Toward... the wilderness?", a fair-play seed) and `tower_sold` with `tagged` (Bricks on the turret he named). Their bark is picked by `pickBark` ignoring the 6 s spacing (its `when`, presence, and once limits still hold), queued behind the line on the panel like a scene, and later barks keep their spacing from it. The events: `CountdownStarted` → `bank_nudge` (wave 2 on, with `BANK_NUDGE_CREDITS` = 250 banked; it waits for the countdown's radio to finish and fires only within the same build phase, D061); `WaveStarted` → `wave_start`; `WaveCleared` → `wave_cleared` and, with no leak from that wave, `perfect_wave`; `EnemySpawned` → `new_enemy` (not in the save's `seenEnemies`); `EnemyDied` → `enemy_killed`; `EnemyLeaked` → `first_leak` (the battle's first; queued), `enemy_leaked` (the first of its type), and `low_integrity` (at 25% or less, once); `TowerBuilt`/`TowerSold` → `tower_built`/`tower_sold` (`tagged: true`, queued, when the sold turret carried the map's name tag); `HoldFireChanged` on → `hold_fire_used`; `NotFiringAtSkitterkin` → `not_firing`; `NeutralHit` → `neutral_hit`; `BossPhase` → `boss_phase`. As the briefing closes (or at once without one): `tower_issued` for each newly issued tower (first, so it wins the moment), `map_start`, and `flag`. `idle` is not wired yet.
- **Scenes by moment:** wave NN's countdown plays `<map>_wNN`; a `ScriptCue` plays the scene with the cue's id (or queues the bark, `cueBark`); as the briefing closes, each newly issued tower plays `<map>_cue_issued_<tower>` (A1M2's Sprinkler announcement, D061); and Bricks's tag moment plays `<map>_cue_name_tag`. A scene plays only if its `when` holds (`scenePlays`).
- **Name tags:** the battle steps `story/tags.ts` over `TowerBuilt`, `TowerSold`, and `WaveCleared` (`tagStep`). The map's tag moment (an `earliest` tag: the first wave clear with an attacking turret standing) plays `<map>_cue_name_tag`, whose line points at the turret (`point: 'firstTower'`); selling the tagged turret fires `tower_sold` with `tagged: true`. As the battle stops, a tag given moves the save's `bricksTagIndex` past this map's name (`tagIndexAfter`; never back). The plate itself is render's to draw.
- **The reply button** on a bark or radio line shows on the panel with its line (`pressCommsButton`): it applies the button's flags and plays its `reply` scene at once, cutting the line. It is not a command and never pauses.
- **Saving:** as a scene ends, its effects (flags, the callsign on the profile) and its id (if it matches `SCENE_ID`) go into the save in play (`withSceneEffects`); a battle's once-per-campaign barks join `story.seen` as it stops.
- **The Denise pointer:** a line with `point: 'firstTower'` (on the panel or in a scene) makes the playfield ping the first-built turret still standing while it shows (`speaking`, D059).
- **Sound:** the line being spoken (`speaking`) ducks the music and plays its speaker's blip as it starts (`blipFor` in `app/audio.ts`; Act I's radio speakers have one). The typewriter's per-character tick is T314's: `setTypeTick` in `ui/dialogue/LineText.tsx` is its hook.
- **The debrief** (`<map>_debrief`) is the results card's (`app/runResult.ts` `debriefLines`): the scene as the run's outcome and the save's flags play it (`linesUntilChoice`: no choice taken; debrief choices are T316's), led by the map's `first_leak` bark when the first leak came in the last 4 s (D028) and that bark could play this run.
- **`?test=1`** turns the comms panel and in-battle scenes off unless `&dialogue=1` (M2's `&radio=1` still works); the briefing still shows, whole and played out at once up to its first choice (nobody is there to pick, so the choice and what follows it don't show), with Clock in focused. `__sd.dialogue` plays a scene or bark by id (`play`, `bark`) and reads what shows (`shown`). The dev dialogue in `ui/dialogue/dev.ts` (a cue with a choice, a full-screen scene, a bark with a reply button) is never in the registries, so only the hooks play it.

## Story state

The profile, flags, seen scenes (and once-per-campaign barks), delivered and read memos, unlocked codex versions, seen enemies, `bricksTagIndex`, and `memorialTower` live in the save ([meta-runtime.md § Save system](meta-runtime.md#save-system)). Choices (D001 #3) are just flags; their payoffs are read by content (tower gifts, allies, map dressing, bark pools, epilogue cards) and by map scripts through `scriptFlags`.

## Other story systems

All pure functions over content and save state:
- `story/counter.ts`: `formatCount` ("1,234,567", locale-independent), `livePestsProcessed` (the save's count plus the run's kills), `resultsCounter(act, run, lifetime, meter?)` (the results line per act, [design/core-loop.md §6.2](../design/core-loop.md#62-results-screen-and-the-lifetime-counter): Act I's line with stars and "Career total: {n}", Act II's with the career line and no stars, Act III's meter line alone, "Held." when the map has none, and the finale's `REMEMBERED: {n}` over the lifetime count), and `countdownDisplay`, the finale countdown `round(N × (1 − restPoints / restTarget))` with progress clamped to [0, 1] ([design/maps.md §5.5](../design/maps.md#55-the-leaving-song-finale-rules)).
- `story/codex.ts`: which versions of each entry are unlocked (`unlockedVersions`, `newCodexUnlocks`), the *Pest Field Guide* / *Field Journal* title (`codexTitle`), and the versions an entry shows (`shownVersions`: the newest, or original beside corrected in the Field Journal, from A3M1). The entries are `content/codex/` (`CodexEntryDef`: an id `codex_<entry>`, a title, a kind, an optional subject, an optional picture, and each version's text, optional small print, and `when`); the act files there (`act1.ts`) are the home of the entry texts.
  - **Unlock rules.** An entry with a subject unlocks when the save meets it: an enemy in `campaign.seenEnemies`, a tower or ability owned. One without (a place, a person, a thing) unlocks by its `when`, which for Act I is `{ mapAtLeast: <the map that lists it> }`, so it unlocks once that map is won. A later version unlocks by its own `when` once the subject is met; one with no `when` never does. Unlocks are never taken back.
  - **The context** between maps is `baseStoryContext(save)` (`meta/story.ts`): the save's flags, seen list, and lifetime count, with `map` the furthest campaign map won (null before A1M1).
  - **Read marks.** Opening an entry adds `codexSeenId(id, version)` (`codex_<entry>__<version>`) to `story.seen` for each version it shows; an unlocked version not there is NEW.
- `story/inbox.ts`: which memos are due (`memosDue`: each memo's `afterMap` won, or null for `memo_a1_00`, and its `when`) and the gifts attached to them, a memo's paragraphs (`memoBody`: the body split at blank lines, then each `extra` whose condition holds), and the unread ones. The memos are `content/memos/` (`MemoDef`: From, To, Subject, body, conditional `extra` paragraphs, sign-off, small print, `afterMap`, `when`, and `gift`); the act files there (`act1.ts`) are the home of the memo texts.
- **Delivery** (`meta/story.ts` `withStoryUnlocks`, pure and idempotent): the enemies a run met join `campaign.seenEnemies` (`enemiesMet`: every group of the waves the run reached, plus the units they bring: a Bunchling's Nibblers, a boss's sneezes and surfacing young), every memo due is delivered with its gift granted once (`story.granted` records the memo id; a gift the save already holds is skipped), then every codex version now unlocked is added. Run end applies it as step 8 ([meta-runtime.md § Run end](meta-runtime.md#run-end)), and the base applies it again on entry (`app/inbox.ts` `catchUpStory`), so a save from before a memo or entry existed catches up. A new save gets `memo_a1_00` delivered by `createNewSave`, and with it the Orbital Strike uplink.
- **The base's tabs** (`ui/screens/Inbox.tsx`, `Codex.tsx`; view models in `app/inbox.ts`): Inbox and Codex come first, open whenever the base is, each with a NEW tag while something in it is unread; the base still opens on Research. Each is a list beside a reader. A memo or entry the pane opens by itself is read after 0.8 s on screen (so arrowing through the tabs reads nothing); one the player picks is read at once. The small print is collapsed under a "Small print" toggle. Up, Down, Home, and End walk a list.
- `story/epilogue.ts`: for each card slot in order, the first `EpilogueCard { id, slot, when: Condition, text }` whose condition matches.
- `story/presentation.ts`: resolves the act dials plus map overrides (loading tip pool, billboard state, Tidybots on or off, jingle variant, UI theme, held medal toasts).
- `story/tags.ts`: Bricks's name tags ([design/towers.md § Bricks's name tags](../design/towers.md#brickss-name-tags)), cosmetic, so outside the sim. The list is `content/dialogue/tags.ts` (`NAME_TAGS`): each name bound to its map, in campaign order, so a replay reuses the map's name. `tagStep(state, simEvent)` returns the new state and its effects (`tagged`: the plate goes on a uid, its text resolved with `resolveText` for A3M3's `{name}`; `untagged`: sold, which plays the `tower_sold` bark with `tagged: true`, or moved). An `earliest` tag goes on the earliest-built attacking tower still standing at the first wave clear with one standing (support towers, with no attack, are skipped). A `latest` tag (A3M3) goes on the newest attacking tower at the map's tag cue (`giveTag`), then moves to each newer one, and to the newest standing one when its tower is sold. `tagIndexAfter` gives the save's `bricksTagIndex`, and `taggedTowerType` A3M3's `memorialTower`.
