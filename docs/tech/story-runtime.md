## Map scripts (story-driven sim changes)

Story moments that change play run **inside the sim** as map data, so headless runs, replays, and the balance harness see exactly what a player sees ([design/maps.md §5.3](../design/maps.md#53-map-scripts)). The `triggers` system ([architecture.md § Entity model](architecture.md#entity-model-typed-pools-not-an-ecs)) evaluates them. Dialogue stays in `story/`; the sim only emits `ScriptCue` ids.

The types are `ScriptedEvent`, `ScriptTrigger`, and `ScriptAction` in [`src/content/types.ts`](../../src/content/types.ts), each trigger and action documented there. An event fires at most once per run unless it sets `once: false`. A trigger `{ wave, phase: 'countdown' }` fires as that wave's build-phase countdown begins (W1's is the pre-game build phase); `{ wreckageCleared: marker }` fires once the drone clears the wreckage under that marker (A2M1's crew logs); `{ objectiveCompleted: id }` fires on the tick after that optional objective settles `done` (cleanup settles it, as it resolves a wave's `cleared`; T706). The finale's triggers: `{ timerFull: id }` fires once that map timer fills (the Deep Bore's breakthrough), `{ phase: n, afterSec }` that long after the script phase reached `n` (Directive 0, 20 s into Phase 2; Dawn's win, 8 s into Phase 3), `{ restProgressPct }` once the song's rest progress reaches it, and `{ echoArrived: id }` once the echo `spawnEcho` sent under that id has reached the song (`EchoArrived`, latched in `state.echoesArrived`; T821). A trigger or action the sim doesn't run is refused by `createSim`, naming the task that lifts it (`SCRIPT_GATES` in [`src/sim/systems/triggers.ts`](../../src/sim/systems/triggers.ts)); every one runs, and the one refusal left is an `openTile` to a buildable tile. An action `{ cue }` is a scene or bark id that story plays; `revokeAbility` serves A3M2's Orbital Strike and, under C4 Keep, the finale's Time Dilation for Phase 2; `bossEnd: 'pivot'` ends a boss's fight as a pivot (`BossEnded { how: 'pivot' }`, `stats.pivotWave` set once, every live hostile unit of its faction stands down, and its `ward` ally takes its place; [enemies.md §6.1](../design/enemies.md#61-boss-scripting)), `standDown: <faction>` stands a faction down on its own (every live hostile unit of it stops, fades out over 1 s and goes: no leak, no bounty, no kill, its wave resolving without it), `setObjective` switches the objective and the meter's label (`ObjectiveChanged`), and `spawnAllies: <group>` starts a refugee group's walk (a bearer group's too: A3M5's, [design/maps.md §5.4](../design/maps.md#54-allies-on-the-map)). `spawnWave: <id>` sends in a script group (`MapDef.scriptGroups`; T706): its units spawn as a wave group's would, from the tick the action runs (an objective's `onComplete` runs in cleanup, so its group starts on the next tick), counted in the wave then running, or the next wave when that one has already cleared; the rules are [`src/sim/scriptGroups.ts`](../../src/sim/scriptGroups.ts)'s header. A2M5's pivot, "whichever comes first", is two events running the same cue, `setObjective: 'escort'` and `spawnAllies`: one on the Penitent's `bossHpPct: 0.5` (its own `pivot` ending ran at that threshold), the other at W6's start with `bossEnd: 'pivot'` and a `{ stat: 'pivotWave', lte: 0 }` guard; the finale's Phase 2, "the later of" the choir at the Halls mouth and W18 cleared (D154), is one trigger, `{ choirAt: 'halls_mouth', afterWave: 18 }`, reached once the choir's leader has reached the marker and that wave has cleared, whichever comes last (`afterWave` names a wave of the map; T820); `setLighting` turns the light to a lighting set at a script moment (the finale's Dawn; `content/lightingSets.ts`), while light that moves across a map's waves is map data, the lighting schedule (`MapDef.lighting`; [design/maps.md §7](../design/maps.md#7-storytelling-with-the-map)); `checkpoint` marks the finale's Phase 2 start ([architecture.md § Checkpoints](architecture.md#checkpoints)); `openTile` targets a predefined decor marker; and `endMap` ends a Holdout as `'completed'` (T605: the map is won on that tick, `'won'` alike, from a map event only; `sim/objectives.ts`). Revocation, forced input, and clickable objects are described below.

`towerUnlockWave: { [towerId]: N }` in map data compiles to `{ on: { wave: N, phase: 'countdown' }, actions: [{ unlockTowerClass: towerId }] }` (A1M1: `{ thumper: 3 }`).

- **Cue ids** follow `<map_id>_wNN` for wave-bound cues (`a1_m01_w03`), and the other `<map_id>_<slot>` forms from [story/style-guide.md](../story/style-guide.md) for the rest. Validation checks the pattern.
- **`when`** is judged once, on the tick its event's trigger is reached ([§ Conditions](#conditions)). If it doesn't hold then, the event is spent without running; it never waits for the condition to come true.
- **Flags in the sim.** `SimConfig.scriptFlags` carries the story flags a map's scripts and setup may read (`ScriptFlagId`: the registry's flags marked `script: true`, now `door_choice`, `spared_quiet_wave`, `stardust_choice`, `quill_choice`), copied from the save by `app/battleSetup.ts` with `scriptFlagsOf` (only flags that are set; defaults never reach the sim). `ConditionDef` tests them with `{ flag, eq }` ([`src/content/types.ts`](../../src/content/types.ts)). The sim never sets flags; story derives flags from `state.stats` when the run ends ([§ Flags](#flags)). C4's in-play effects are flag-conditioned: Purge's armor modifier and QUILL's offline map are `C4_IN_PLAY` (meta-runtime.md § Story transactions), System Reboot's lock is A3M5's own `lockedAbilities` row; the rules are in [design/core-loop.md](../design/core-loop.md) §6.11.
- **Forced input** (`sim/forcedInput.ts`, T605). `forceInput: { id }` sets `state.pendingInput` and emits `ForcedInputRequested` (a second request while one waits is ignored). While it is set, `runTick` runs only `applyCommands`: the wave schedule, movement, firing, statuses, cooldowns, script triggers, and timers are frozen from the rest of the action's own tick on. The sim still ticks (so render can animate and `tick` stays monotonic), and `applyCommands` rejects every command `forcedInput` except `{ type: 'scriptInput', id }` with the pending id, which clears it, records it in `state.forcedResolved`, and emits `ForcedInputResolved`; that tick then runs whole, and its triggers reach `{ forcedInputResolved: id }` (A3M3: `endMap`). The host shows the single-button overlay on `ForcedInputRequested` (`app/forcedInput.ts`; the SEAL screen as built is [core-loop.md §2.11](../design/core-loop.md#211-scripted-moments)). The ids and how each shows are content (`content/forcedInputs.ts`, `FORCED_INPUTS`): A3M3's `seal` ("SEAL", `door_hum`) and the finale's `whos_there` (`WHOS_THERE_INPUT`: "Who's there?", permitted by `fin_m01_cue_directive0`'s last line, no hum), which map data and dialogue import. Real-time lines (Bricks's line after 20 s on the SEAL) are a story-side timer on wall-clock time, not sim ticks. The balance harness presses it with a `scriptInput` build step (and the policy builds press it as par does).
- **Clickable world objects** (`sim/clickables.ts`, T409). The map lists its clickable markers, each with the name the cursor and the screen reader give it (`MapDef.clickables`). `{ setClickable: { marker, on: true, fallback? } }` makes one clickable (`state.clickable`, with its fallback beside it in `state.clickFallback`) and emits `ClickableChanged { on: true }`; render highlights it ([art-direction.md §6](../art/art-direction.md#6-story-and-world-sprites)) and screen readers hear "<name>: within reach." (also, silently, as a battle binds with one already clickable: a resumed checkpoint; `bindClickables` in `app/peeker.ts`, D135). While it's clickable, an `interact { marker }` command (from a click or Enter on it, armed or not; it's in the command log, so headless runs replay it) interacts with it; any other time it's rejected `notClickable`. If the player never clicks, the fallback does it for them: each tick, before the events, a clickable marker whose fallback trigger is reached is interacted with by the sim. Either way it happens **once**: the marker moves to `state.interacted`, `ClickableChanged { on: false }` then `Interacted { marker, byFallback }` are emitted, and the map's `{ interacted: marker }` trigger is reached (on the same tick, or the next one for a click applied while paused). The rules at the edges: a marker already interacted with never turns clickable again (`setClickable` on is then a no-op); turning on a marker that's already clickable only replaces its fallback; `on: false` withdraws it and drops its fallback, so a withdrawn beat never lands by itself. A fallback is any trigger an event may use (`createSim` refuses one it can't run). The balance harness clicks with an `interact` step ([conventions.md § Balance sims](conventions.md#balance-sims-npm-run-sim)). Pebble's A2M3 rescue is built this way: `setClickable` on W3's clear (W4's build phase, the one hands-free window in every build; D135) with "W6 cleared" as its fallback, and `{ interacted: 'peeker' }` cueing the rescue scene (flagged `pause: true`, so it plays as a pausing panel; [§ Dialogue runner](#dialogue-runner)), for example:

  ```ts
  { id: 'pebble_on', on: { wave: 3, phase: 'cleared' },
    actions: [{ setClickable: { marker: 'peeker', on: true, fallback: { wave: 6, phase: 'cleared' } } }] },
  { id: 'pebble', on: { interacted: 'peeker' }, actions: [{ cue: 'a2_m03_cue_pebble' }] },
  ```

  As the rock lights up (`ClickableChanged` on the `peeker` marker) the app plays `peeker_lights_up` once (a double squeak and a soft chime, never ducked under a line; D135), and a click plays the Act I Peeker's `peeker_squeak` (`bindClickables` in `app/peeker.ts`; never during a checkpoint replay). Clicks that change nothing in the sim (poking the Peeker in Act I) are UI events instead (`peeker_poked`, [§ Flags](#flags)).
- **Revocation** (`sim/revoke.ts`, T606) runs from map events only (an objective's `onComplete` can't: it needs the run's loadout and slots). `revokeTowerClass` selects the class deterministically (`mostInvested` over the loadout's classes of its `faction`, every class without one: most credits invested, then most towers placed, then loadout slot; [design/towers.md §9](../design/towers.md#9-rules-for-story-driven-tower-changes)), folds every tower of it away with `refundPct` of what was paid (`TowerRevoked` each, booked in `stats.creditsRefunded`), adds it to `state.revoked.towers` (its towers' uids to `revoked.uids`), counts it in `stats.revocations`, and emits `ClassRevoked` with the total; a loadout with no candidate loses nothing. `revokeAbility` adds the ability to `revoked.abilities` (counted too) and emits `AbilityRevoked` with the slot that held it (null if neither); a strike already cast still lands. `setModifier` turns `quillLockout` or `previewHidden` on or off (`ModifierChanged` on a change): either hides the wave preview (`previewHidden(state)`), and `quillLockout` also darkens slot 2 when it holds the map's companion's ability and that ability names the modifier as its `lockedOutBy` (QUILL's Time Dilation: the data names the slot, the sim names no companion; `slotRevoked`). From then on a build of the class, any command naming one of its folded towers, and a cast from a dark slot are rejected `revoked`. A checkpoint replay re-runs the cue from the command log, so it pays once. The balance harness forces the class with `SimConfig.revokeClass` (its per-class story variants). Meta saves `revoked` on the run that first wins the map (run end's step 3, [meta-runtime.md § Run end](meta-runtime.md#run-end)).
- **The lockout in the app** (`app/revoked.ts`, T606; the HUD's look is T631's, [art-direction.md § Look](../art/art-direction.md#look-a-sci-fi-tactical-hud)'s *Act III HUD*): the HUD's `revokedHud` (`ui/hud/revokedState.ts`) follows the sim; the preview reads ACCESS RESTRICTED with **the leak line slot** under it, which story fills as QUILL's leak line plays (`setLeakLine`: a `<map>_cue_leak_<x>` cue scene's first line) and which clears as the next wave starts. ## Dialogue runner

A pure state machine over dialogue data (`src/story/runner.ts`): `start(scene, ctx) → cursor` and `advance(scene, cursor, ctx, choiceIndex?)`. A cursor rests on a line, a choice, or the end; `branch` and `set` nodes run on the way, and the effects (flags set, the callsign) ride on the cursor for meta to save when the scene ends (with the scene id in `story.seen`).
- **Choices:** `advance` at a choice needs a valid option index (it throws otherwise). The option's `set` flags join the effects, and a branch later in the scene sees them (the save's flags with the scene's laid over). The cursor's `chose` is the option just taken, so the UI can show its "{Speaker} will remember that." (`remember`).
- **The end:** an `end` node, or falling off the last node. `advance` at the end returns the same cursor.
- **Resuming:** a cursor is plain data. A saved `index` and `effects` resume with `resume(scene, index, effects, ctx)`.
- **Gates:** `scenePlays(scene, ctx)` judges a scene's `when` as its trigger fires; `start` doesn't check it.
- **Bark buttons:** `pressButton(button)` gives the flags to set and the reply scene to play.
- **Read-through:** `readThrough(scene, ctx)` plays a scene with nobody advancing it, up to its first choice or its end: the lines it shows and the cursor it rests on, with the effects its `set` nodes gave on the way (`linesUntilChoice` is just the lines: the results card's debrief).
- **Loops:** a chain of branch and set nodes longer than the scene throws (validation refuses such loops first).

**The data shapes** are [`src/content/dialogue/types.ts`](../../src/content/dialogue/types.ts), one-to-one with [style-guide §5](../story/style-guide.md#5-dialogue-format-conventions): `Scene` (an id and its nodes, with an optional `when`), the node kinds `line` (speaker, expression, text, `durationSec`, an optional reply `button`, and an optional `plateAs`: the plate's name for this line instead of the speaker's, 1–16 characters, `[dialogue-plate]`; A3M1's first Bramble line reads "The Matriarch" until Pebble names her, D143), `choice` (2–3 options, each with `text`, `tone`, the flags it `set`s, `goto`, and `remember`), `branch` (`cond`, `goto`, `else`; `goto`, not `then`, because lint refuses thenable object literals), `set` (a flag and one of its declared values, or the callsign), and `end`; `Bark`, `BarkTrigger`, `Condition`, and the token and glyph ids. The types make a bad speaker, a bad expression for a speaker, or a flag value outside its declaration a compile error.
- **Labels.** Any node may carry a `label`; `goto` and `else` name a label in the same scene. A choice option without `goto`, and a branch without `else`, continue with the next node.
- **Files.** Each map's scenes and map-scoped barks are `content/dialogue/a<act>/<map_id>/scenes.ts` and `barks.ts`, listed once: Act I's in `content/dialogue/index.ts`, a later act's in its act file (`content/acts/a2.ts`, `a3.ts`, `fin.ts`), which loads with that act's lazy chunk ([architecture.md § 5, *Lazy chunks*](architecture.md#5-build-test-and-deploy)); the registry is `MAP_DIALOGUE`, with `SCENES` and `BARKS` by id, holding the acts loaded so far. Barks that can fire on several maps are `SHARED_BARKS` (`content/dialogue/barks/`: Act I's one file per trigger, `<trigger>.ts`; Act II's one file, `act2.ts`; Act III's, `act3.ts`, Prim's PA greeting Everglow Security's part-two units on `new_enemy`), each gated by its `when`. A2M4's, A2M6's, and A3M1's folders have a `base.ts` for their base scenes, which file as `<map>_base_<name>`: act2.md's `base_a2_loophole` is `a2_m06_base_loophole`, act3.md's `base_a3_survey` is `a3_m01_base_survey` and its `base_a3_night_shift` is `a3_m04_base_night_shift`; `tools/dialogueCanon.test.ts` checks every registered map's section heading in its act file and each line against it.
- **What plays a scene** is its id's slot (`<map_id>_<slot>`, [style-guide §5.3](../story/style-guide.md#53-ids); `sceneSlot(id)` parses it, `parseSceneId` in `content/dialogue/rules.ts`): `brief` (the briefing), `w<NN>` (the radio as wave NN's countdown begins), `cue_<name>` (a map script `{ cue }` with the scene's id, or one of the moments app/dialogue.ts plays by name: `cue_name_tag` at Bricks's tag moment, `cue_issued_<tower>` for a newly issued tower at the battle's start; [§ Dialogue in play](#dialogue-in-play)), `debrief` (on the results card), `scene_<name>` (a full-screen scene a cue plays, or the results flow: a win's scenes before Results and after it's dismissed, `content/dialogue/resultsFlow.ts` and `app/runFlow.ts`), and `base_<name>` (a base conversation topic, played as a panel over the base by `app/baseScenes.ts`, while dialogue is on: the **visit scenes** (`VISIT_SCENES`), each once, on the first base visit whose moment has come, several in turn: A1M3's `arrival` with the shop open, A2M4's `handover` (Bricks hands Pebble to Goldie) once A2M4 is won, and A2M6's `loophole` then `whistle` once A2M6 is won (a row can stage its scene full-screen, `mode: 'fullscreen'`: the whistle, Act II's last image, plays on the dark stage like Ishael's debrief, while the loophole stays a panel; D139), A3M1's `survey` once A3M1 is won, and A3M4's `night_shift` (`NIGHT_SHIFT_SCENE`) once C4 is answered (only A3M4's debrief sets it), mandatory (D146: the row's `noSkip`, `PlayOptions.noSkip`: Esc takes the key and skips nothing, every line is read with Next, a silence moving on by itself; full-screen, on its stage in the shelters, `night_shift`) (all of them wait for an unanswered debrief choice, C2, which the base offers first as its own panel, `app/baseChoice.ts`, D138); a visit scene not registered yet is never due; and A1M3's `stardust`, the early ask, from the shop's open-question row).
- **Speakers** are the ids in [style-guide §5.1](../story/style-guide.md#51-speaker-ids), registered in [`content/dialogue/speakers.ts`](../../src/content/dialogue/speakers.ts) with the name plate, its color, the typewriter's blip (`blip.<speaker>`, authored by audio), the frame (`portrait`; `icon` for Gerald, whose text shows as a teal status readout, `dlg-status`; and for portrait-less speakers their text style: `pa`, `form` for `kfa`, `distorted` for `hollow`, `caption` for `narrator`, `ui` for `system`), and the portrait sprite.
- **Portraits** are one sprite per speaker, `portrait.<speaker>` (`src/content/sprites/portraits/`). Its frames are `[<variant>.]<expression>[_talk]` (`neutral`, `neutral_talk`, `party_hat.policy`), with QUILL's `policy_flash` for the tell; the portrait list is in [art-direction.md § Portrait roster](../art/art-direction.md#portrait-roster).
- **Expressions:** the five base expressions plus per-speaker extras (`EXPRESSION_EXTRAS`: `quill.policy`, `pebble.singing`, `thrum.singing`, `vesthara.laugh`, each with the base expression art falls back to). A line naming no expression uses `neutral`; speakers with no portrait (and Gerald) take none.
- **Portrait variants** are chosen by rules, not by lines: `speakers.ts` lists, per speaker, `{ variant, when: Condition }` in priority order, and the first that holds wins (for example `vesthara`: `touched_deep` in Act III, `touched` from this run's A2M5 pivot on (`{ runStat: 'pivotWave', gte: 1 }`, so a replay starts her untouched) and every map after; `bricks`: `pebble` from A2M4, and on A2M3 once `a2_m03_cue_pebble` is seen, which the cue's end writes to the save, so the portrait changes mid-battle, but not on A2M6, where Pebble is in Dome 3 (battle and debrief), except for the whistle scene (after QUILL's loophole is seen, before the whistle is; D138); `pebble`: `cap` (Bricks's bottle cap) from A2M4, `patch` from A3M3; `quill`: `damaged` under `quill_choice = keep` once this run answered Directive 0's "Who's there?" (`{ inputResolved: 'whos_there' }`, through Results, C5, and the epilogue, which read the ended run) or, off the finale map, after Dawn was seen, `purge` under `quill_choice = purge`, `party_hat` on A1M5; `party_hat` on all of A1M5 for Bricks, Sterling, Kip, Goldie, and Zibzab too (Sterling's memo: "Hats on", so from the briefing); `vesthara`: `dawn` from the finale's Phase 3 (`{ phaseAtLeast: 3 }`, the battle's or the ended run's) or, off the finale map, once `fin_m01_scene_dawn` is seen, so a replay of the finale starts before Dawn; Ves'thara's `touched_deep` and Goldie's `act3` hold in Act III and the finale; `sterling`: `remote` on A3M5, her boss cues by live feed; `kip`: `act2` (the coat) in Acts II and III, `act3` (the pin left on the console) from his silence in A3M5's briefing on: once `a3_m05_brief` is seen, and on every map after). A rule may also say how the variant takes a silence (`silence: 'blink'`: a present speaker's silence flaps the talk frame twice a second, `PortraitView.blink`, still under reduced motion; QUILL's Purge status bar in Night Shift), that it has no `policy` tell (`noPolicy`: Purge's QUILL), and that it holds for the speaker's silences only (`silenceOnly`: Kip's `act3` on A3M5 before the briefing is seen, so his ledger line wears the pin and his silence doesn't; D150). A replayed scene looks as it first played: its lines judge their speaker's variant and plate with that scene not yet seen (`lineView`'s `scene`), so A3M5's briefing shows the pin on every run (D151). Bricks's `dark` (the derived bake, for an absent speaker) is not a rule.
- **Name plates** follow the same pattern: a speaker's optional `names` lists `{ name, when }` in priority order, the first that holds replacing its `name` on the comms and dialogue panels (`pebble`: `???` until `a2_m03_w07`, where Bricks names her, is seen, and on every map from A2M4; D103; `chitterbloom`: "Bramble" from A3M1, where Pebble names her in the briefing, so every line of that map, Ves'thara's translations before Pebble's included, reads Bramble).
- **Silence:** a `line` with `text: ''` shows the speaker's frame (dark for a speaker absent from the radio, and for Bricks after A3M3 anywhere) for `durationSec`, with no text and no typing sound. In a briefing or a pausing panel the speakers are in the room, so only one gone for good shows dark (`lineView`'s `present` is null there); the briefing's log writes a silence as "…" under its plate.

## Conditions

Story conditions are data, not strings (`Condition` in [`content/dialogue/types.ts`](../../src/content/dialogue/types.ts), evaluated by `evaluateCondition` in `story/conditions.ts` over a `StoryContext`: the flags, the map the story is about, the lifetime counter, the save's `story.seen`, the objectives on file, the run that just ended, and the battle in play's stats):
- `{ flag, eq }`: the flag's value, or its default while unset.
- `{ act }`, `{ mapAtLeast }`, `{ mapIs }`: campaign map ids, built or not, in `content/campaign.ts` order. Before A1M1 (the intake, `map` null) the act is 1 and no map test holds. A post-game map's dialogue (a challenge's briefing) reads as the finale's, `fin_m01` (`app/dialogue.ts` `storyMapOf`, D156), so Pebble keeps her name, Bricks's cap and its patch there.
- `{ stat: 'pestsProcessed', gte }`.
- `{ bank: 'stardust' | 'intel', gte?, lte? }`: the save's bank of that currency (`StoryContext.bank`, the save's `currencies`, filled by `baseStoryContext`) is within the bounds, inclusive. A2M4's debrief tests `{ bank: 'stardust', lte: 0 }` for C2's `none` ("No refunds. I did say."): with nothing to trade, no offer. False without a bank.
- `{ seen: <scene or bark id> }`: the id is in `story.seen` (scenes played, once-per-campaign barks).
- `{ objectiveDone: { map, objective } }`: that map's optional objective is on file in the save (`MapRecord.objectives`, recorded on a win, never taken back); `StoryContext.objectives` carries them, filled by `baseStoryContext`. A2M1's crew-log codex entry unlocks on `{ map: 'a2_m01', objective: 'crew_logs' }`. (The sim's in-map `objectiveDone`, below, is another atom: it reads this run's objectives.)
- `{ revokedTower: <tower id> }`: that class is revoked in the save (`unlocks.revokedTowers`, A3M2's Clean Exit until the jailbreak; `StoryContext.revokedTowers`, filled by `baseStoryContext`). Bricks's A3M3 briefing line when the Thumper was taken (D143). False without the list; validation refuses an unregistered tower.
- `{ all: [...] }`, `{ any: [...] }`, `{ not: … }`.
- `{ phaseAtLeast: n }` and `{ inputResolved: <forced input id> }` (T809): this run's script phase (`state.phase`: the finale's 1–3) is at least `n`, and this run resolved that forced input (`state.forcedResolved`; the ids are `content/forcedInputs.ts`'s). Like `runStat` they read the bound battle (`StoryContext.liveScript`, filled by `app/dialogue.ts`), else the ended run (`RunContext.script`, which the router fills from the sim as the run ends, so the scenes after Results still read it), and are false outside a run. For the finale's portraits: Ves'thara's `dawn`, QUILL's `damaged`.
- Two that read the run that just ended, so they hold only in a debrief, on Results, and in run-end barks: `{ outcome: 'won' | 'lost' }` and `{ thisRun: <boolean flag>, eq }`. `thisRun` is the value that flag's run-end rule gives over this run, set or not; C1's lines read *this run*, its payoffs the flag. Without a run both are false, and so is `thisRun` when the ended map has no rule for that flag. `runContextOf(map, outcome, stats)` builds the run context from the map's rules, with the run's final `runStat` stats.
- `{ runStat, gte?, lte? }` (T569): this run's counter (`RUN_STORY_STATS`: `pivotWave`, `evacuated`, `refugeesLost`, `revocations`, the sim's `SimStats` of those names) is within the bounds, inclusive. It reads the battle's live stats (`StoryContext.live`, which `app/dialogue.ts` fills from the sim while a battle is bound), else the ended run's (`RunContext.stats`, on Results); outside a run it is false, and it never reads the save. It is for what must follow this run's moment rather than the campaign's: Ves'thara's A2M5 `touched` (`pivotWave` ≥ 1, so a replay starts her untouched), and A3M2's lines after the Clean Exit (`revocations` ≥ 1), where a `seen` test would hold from a replay's first tick.

**In-map conditions** (the Challenge medal, optional objectives, and script `when` guards) use the sim's `ConditionDef` ([`src/content/types.ts`](../../src/content/types.ts)), evaluated by `src/sim/conditions.ts` over run state. Its atoms, by when they are judged ([design/progression.md §3](../design/progression.md#3-medals-and-intel), "Evaluation"):

| Atom | Reads | Judged |
|---|---|---|
| `{ towers: { tower?, faction? }, gte?, lte? }` | Live towers of that tower id or faction (all towers if neither) | As things stand (a medal's on the win tick) |
| `{ linkActive: LinkId }` | At least one pair of that synergy link is active | As things stand |
| `{ tagRatio: { tag, of: 'leaked' \| 'killed', gte } }` | That tag's leaked or killed units ÷ its spawned units (false when none spawned) | As things stand |
| `{ restedPct: share }` | The finale's Phase 2 Hollow kills laid to rest inside the song ÷ all of them, laid to rest or scattered (`stats.restedKills`, `scatteredKills`; false with none). The Laid to Rest medal is `{ restedPct: 0.6 }` ([design/maps.md §5.5](../design/maps.md#55-the-leaving-song-finale-rules)); only a map with a `song` may use it | As things stand |
| `{ phaseAtLeast: n }` | The map's script phase (`state.phase`, raised by `setPhase`; the finale's 1–3) is at least `n` | Settles true once reached (phases only rise) |
| `{ stat: RunStat, gte?, lte? }` | A run counter (`integrityLost`, `towersBuilt`, `creditsSpent`, `abilityUses`, …; `heavyLeaks` counts leaks by Heavy units: A2M1's Hiccup Contained is `{ stat: 'heavyLeaks', lte: 0 }`; `pivotWave` is the wave a boss's pivot ran in, 0 until it does, set once: A2M5's Kneel is `{ stat: 'pivotWave', gte: 1, lte: 5 }`; `evacuated` and `refugeesLost` are an Escort's refugees safe at the exit and lost); counters only grow, except `evacuated`, which an enemy at the exit takes one from | Over the run |
| `{ passedMarker: { marker, enemy?, unrevealed? } }` | A unit of `enemy` (any enemy if omitted) went past the marker at some point: its route distance passed the route point closest to the marker (the later one where a route doubles back). With `unrevealed: true`, only a unit never Revealed since it spawned counts (`Enemy.everRevealed`; A2M4's Nothing Unseen is `not` this on `intake_b` for the Veilwalker). Medal-exempt units never count. Latched each tick in `stats.markersPassed` | Over the run |
| `{ leaks: { faction?, enemy?, waves? }, gte?, lte? }` | Leaks by that faction or enemy id (every leak if neither); medal-exempt units never count. Counted by movement in `stats.leaksByFaction` and `leaksByEnemy`. `waves: [from, to]` counts only units that spawned in those waves, inclusive (`stats.leaksByWave`; not combined with `faction` or `enemy`; A2M6's Before the Dark, no leaks in the last three waves, is this with `lte: 0`) | Over the run |
| `{ wreckageCleared: marker }` | The salvage drone cleared the wreckage tile under that marker (A2M1's crew logs) | Over the run |
| `{ cleared: MarkerId[], byWave }` | Every listed wreckage marker was cleared before wave `byWave` starts (A3M5's Cut the Feed). From that wave on it reads the drone's count of cleared tiles as the wave started (`state.wreckageAtWave`, recorded by the triggers system on a map that uses the atom); a tile the drone finishes on the wave's starting tick counts, since the wreckage system runs before the waves | Settles true once all are cleared in time, false once that wave starts without them |
| `{ objectiveDone: id }` | Another optional objective of the map is `done` (never itself). It reads the objective live: one still open whose condition has settled true reads done, so a `when` judged on the tick it settles agrees with it (A3M5's W10 surge on the tick the last feed line clears) | Settles when that objective's condition does |
| `{ flag, eq }` | `SimConfig.scriptFlags`; an unset flag never matches | Fixed for the run |
| `{ all }`, `{ any }`, `{ not }` | Combinators | — |

A condition **settles** once the rest of the run can't change it (`settledCondition`): a flag at once, a `stat` past its `lte` (false) or at its `gte` with no `lte` (true), a `passedMarker`, `wreckageCleared`, or `phaseAtLeast` once reached (true), a `leaks` count like a `stat`, an `objectiveDone` when its objective's condition does, a `cleared` true once all are cleared in time and false once its wave starts without them, and the combinators by three-valued logic. State atoms stay open until judged. That is how a Challenge such as A1M2's "no Brood Hauler gets past the pump station" (`{ not: { passedMarker: { marker: 'pump_station', enemy: 'hauler' } } }`) is forfeited the moment one does ([architecture.md § Medals](architecture.md#medals)). The validator's rules for conditions and medals are in [`src/content/validateMedals.ts`](../../src/content/validateMedals.ts).

## Flags

Flags are declared in `content/dialogue/flags.ts` (`FLAGS`): each with its `values` (a boolean flag lists `true` and `false`; a choice lists its ids, such as `'convoy'`, `'warren'`), a `default`, an optional `script: true`, and a one-line description. `FlagId` and `ScriptFlagId` (`content/types.ts`) are derived from it, so a typo'd flag is a compile error, and a map's `flagVariants` may list only that flag's values. The registry is exactly the canonical flag table, [story/campaign.md](../story/campaign.md) §6.2, in its order and with its values (`tools/flagLedger.test.ts` checks it; the bible's table is a summary).

- **Defaults** are what story reads while a flag is unset (`flagValue` in `src/story/flags.ts`): `false` for a boolean (not done yet), `null` for a choice not made yet. The sim never sees a default ([§ Map scripts](#map-scripts-story-driven-sim-changes)).
- **Who sets them:** the intake (`arrival_reason`, T306), `choice`/`set` nodes, UI events (`peeker_poked`, `asked_zibzab_early`, optional bark buttons), or **run-end rules**.
- **`peeker_poked`** (T309) is written the moment the Act I Peeker is first poked (`app/peeker.ts`, through `updateActiveSave`), not at run end: a poke on any Act I map counts whether that run is won, lost, or abandoned, and the run end builds on the same in-memory save, so it keeps the flag. Later pokes write nothing. A battle with no save in play (`?map=`) sets nothing.
- **Saves** hold `story.flags` keyed by `FlagId`, each value one of the flag's declared `values` ([meta-runtime.md § Validation](meta-runtime.md#validation)).

**Run-end rules** (`FLAG_RULES` in `content/dialogue/flags.ts`) derive a boolean flag from the finished run's `state.stats` when a map ends:

```ts
{ flag: 'spared_quiet_wave', onMapEnd: 'a1_m05',
  value: { tagRatio: { tag: 'quiet_wave', of: 'leaked', gte: 0.75 } } },          // design/core-loop.md §2.7
{ flag: 'held_fire_second_look', onMapEnd: 'a2_m03',
  value: { all: [{ tagRatio: { tag: 'fleeing', of: 'leaked', gte: 0.5 } },
                 { stat: 'holdFireUses', gte: 1 }] } },                          // plain Hold Fire only
```

- **The grammar** (`FlagRuleCondition`) is the sim's condition atoms that make sense after a run: `tagRatio` (leaked or killed ÷ spawned for a wave tag; false when none spawned), `stat` over the run counters `holdFireUses`, `holdFireTicks`, `integrityLost`, `towersBuilt`, `creditsSpent`, and `abilityUses` (`gte`/`lte`), and `all`, `any`, `not`. `holdFireUses` counts only plain Hold Fire turned on, never the Spare runners filter ([architecture.md § Commands](architecture.md#commands-input-into-the-sim)).
- **When they apply:** `src/story/flags.ts` `runEndFlags(mapId, stats)` evaluates the rules whose `onMapEnd` is the ended map, and meta's run end applies them only on the run that **first wins** that map ([meta-runtime.md § Run end](meta-runtime.md#run-end), step 2). Each rule sets its flag to `true` or `false`, so the flag is always set once the map is won. Losses and replays never change it: the map's results stamp, its memo, and every later payoff follow the run that completed the map.
- **The harness** judges C1 with the same rule: assertion #16(a)'s held run must make `spared_quiet_wave`'s rule true ([conventions.md § Balance sims](conventions.md#balance-sims-npm-run-sim)).

## Text substitution

`story/text.ts` runs on every line, bark, choice, memo, codex version, tip, results line, and epilogue card:

| Token | Resolves to |
|---|---|
| `{name}` | `profile.name` |
| `{callsign}` | `profile.callsign` (Sprout, Thorn, Waykeeper; `CALLSIGNS`) |
| `{they}` `{them}` `{their}` `{theirs}` `{themself}` and capitalized `{They}` `{Them}` `{Their}` `{Theirs}` `{Themself}` | The forms from `profile.pronouns` (`PRONOUN_SETS` in [`content/dialogue/profile.ts`](../../src/content/dialogue/profile.ts): `she`, `he`, or `they`, each with all five forms and its `agreement`) |
| `{v:<plural>\|<singular>}` | Verb agreement: the first form when `agreement` is `plural` (they/them), the second when `singular` (she, he). Any pair works: `{v:are\|is}`, `{v:were\|was}`, `{v:have\|has}` |
| `{pests_processed}` | The lifetime counter with thousands separators; inside a map it is the save value plus the run's `skitterkinKilled` so far |
| `{evacuated}` | The current map's meter count (Evacuated, Sheltered, or Voices); 0 outside a map |
| `{glyph:<id>}` | An inline glyph from the pixel font's glyph set (`sun`, the Evie sun used in memo sign-offs; `star`, the results-screen ★). Unknown ids fail validation |

**Before the intake** (a profile of null, which a v1 save has until the intake runs on Continue), tokens read `NO_PROFILE`: "Technician", Sprout, and they/them. An unknown or malformed token throws (validation catches it first). `{glyph:…}` resolves to one character for the renderer to draw: `★` for `star`, and the private-use `U+E000` for `sun` (`GLYPH_CHARS`). The token grammar, the worst-case lengths, and the limits live in `content/dialogue/rules.ts`, so validation can read them (content never imports story); `story/text.ts` re-exports `worstCaseLength` and `tokenProblems`.

Emphasis `*word*` (at most one per line) renders italic; parentheticals such as `(hum, six notes)` and `(squeak)` are plain text. Lines from `hollow` render in the `distorted` style (dropped letters and misregistered glyphs, cosmetic RNG, reduced to plain grey text in reduced-motion mode).

## Validation

`content/validateDialogue.ts` (run by `validate.ts`, so by the content test and `compileContent`) enforces the style guide's mechanical rules over every scene, bark, and name tag. Its header lists each rule by name; in short:
- **Lengths after worst-case substitution** ([style-guide §5.4](../story/style-guide.md#54-text-tokens-and-length)): `{name}` counts 16, `{callsign}` 9, `{pests_processed}` 9 ("1,234,567"), `{evacuated}` 5, pronoun tokens their longest form, `{v:…}` its longer form, `{glyph:…}` 1. Limits (`TEXT_LIMITS`): dialogue line 120, bark 80, choice option 60, bark button 16, name tag 16, codex version 600, memo body 600 and small print 140, loading tip 80, shop description 100, epilogue card 240. Scene sizes count the lines of the longest play-through (each branch on its own): briefing ≤ 8 lines, radio slot 1–3 (4 when its first line carries a reply button: A3M6's knock-knock, whose ignored ending mirrors the reply's; `RADIO_REPLY_MAX_LINES`), mid-map cue ≤ 4 (a cue that pauses the battle, `pause: true`, ≤ 6: its panel is effectively a scene; A3M2's Clean Exit), full-screen scene ≤ 20, debrief ≤ 6, base topic ≤ 8.
- **Ids and references:** every speaker exists; every expression exists for its speaker (none for a speaker without a portrait); tokens parse; scene ids match `<map_id>_<slot>` under their own map; bark ids start with their speaker and (for a map's barks) name its act; ids are unique; a reply button's `reply` and a `seen` condition name registered ids.
- **Protected `{name}`:** it may appear only in scenes and barks for maps at or after `a3_m03` in campaign order (a shared bark's `when` must imply that), in `system` copy (name tags, onboarding), and in epilogue cards, and never in a `sterling` line.
- **QUILL's tell:** a `quill` line uses expression `policy` if and only if its text starts or ends with "(Per policy.)".
- **Exclamation budget:** `bricks` and `vesthara` lines never contain `!`; in Act III scenes only `sterling` and `pebble` lines may; `quill` never does after A3M2; in the finale only `pebble`, `sterling`, and `system` (the final lyric) may. Choice options and button labels count as the player's. A shared bark's act is the one its id names. Softer per-act guidance stays with writers.
- **Shape:** at most one `*emphasis*` per line; a silence line has `durationSec` (and every duration is > 0); a `choice` has 2–3 options; a `remember` appears only on C3 and C4 choices (one setting `door_choice` or `quill_choice`); dialogue never sets a flag a run-end rule owns (so C1 is never a choice); reply buttons ride only on radio and cue lines.
- **Flow:** labels are unique in a scene and every jump names one; every node is reachable from the first; no loop runs through branch and set nodes alone.
- **Conditions and barks:** `thisRun` names a flag with a run-end rule; `outcome` and `thisRun` appear only in debriefs and full-screen scenes; a `bank` or `runStat` test has a bound, each a non-negative integer, with `gte` ≤ `lte`, and a `runStat` names a run story stat and never sits in a base topic (no run there), nor does a `phaseAtLeast` (a whole number from 1) or an `inputResolved` (a forced input `content/forcedInputs.ts` names); a `revokedTower` names a registered tower; a line's `plateAs` is 1–16 characters (`[dialogue-plate]`); a `tower_revoked` bark is a map's, never shared; bark trigger waves and phases are positive integers; a `flag` bark has a `when`; `cooldownSec` is > 0 and never set with `once`.
- **Pausing cues** (`[dialogue-pause]`, T501l): `pause: true` only on a `cue_<name>` scene. A briefing, a full-screen scene, and a base topic hold input already; radio and debriefs never pause.
- **Name tags** are on planned maps, in campaign order.
- **Epilogue cards** (`content/validateEpilogue.ts`, run with the dialogue's): a card reads only the flags its slot lists, with values those flags hold; its text has known tokens and is at most 240 characters at worst; in each slot, every combination of its flags' values resolves to a card unless the slot is `optional`, and no card is shadowed by the ones before it. An empty card list is the epilogue not written yet and passes; once one card lands, the whole set must.

## Barks

Scenes and barks bind to triggers: map script cues (`ScriptCue`), bark-matrix events (the trigger ids and their exact conditions are owned by [design/core-loop.md §6.3](../design/core-loop.md#63-barks); each maps to a sim event or a host event), and menu events (entering the base, the shop, the star map, the Inbox). `story/barks.ts` picks barks by the style guide's priority (script cue → boss → first-time trigger → repeat), spacing (one per 6 s of sim time unless scripted), presence (QUILL and the companion only; QUILL is absent when `quillOffline`), and no-repeat pools, using its own seeded RNG. A bark slot assigned to an absent speaker plays that speaker's authored silence line. The state (`BarkState`, from `newBarkState(seed)`) is plain data the caller keeps per battle:
- **`pickBark(pool, event, state, ctx)`:** an event is a trigger with its parameters, the sim time, and the speakers present. A bark is a candidate when its trigger matches (the same id, and every parameter the bark names equal to the event's), its `when` holds, its speaker is present (or its text is `''`, a silence, which plays for an absent speaker), and it is available. **Available:** a bark with neither `once` nor `cooldownSec` plays once per map; `once: 'campaign'` also skips barks in `story.seen`; a bark with `cooldownSec` repeats once that much sim time has passed. The most specific candidates win (a tagged `tower_sold` over the generic one); among them unplayed ones come first, then a seeded draw. Within 6 s of the last bark nothing plays, and nothing queues.
- **`pickBarkOf(pool, events, state, ctx)`:** the events of one moment, tried in priority order (a boss trigger, or `boss_phase`; then a trigger's first firing this map; then repeats), at most one bark, every event counting as fired.
- **`cueBark(bark, atSec, state)`:** a bark a map script cue names plays regardless of spacing, presence, and once limits, and later barks keep their spacing from it.
- **Never a reply:** a bark is always its own radio batch. The comms panel never shows it under another speaker's line as if it answered it (D061); authored replies are the next line of the same scene, or a button's `reply`.
- After a battle, `campaignBarksPlayed` lists the once-per-campaign barks to add to `story.seen`.

`BarkTrigger` ([`content/dialogue/types.ts`](../../src/content/dialogue/types.ts)) carries core-loop's trigger ids with their parameters (`enemy_killed`, `enemy_leaked`, and `new_enemy` name an enemy; `tower_built`, `tower_sold`, and `tower_revoked` may name a tower (and `tower_built` `highGround: true`, a tower built on a `^` tile: A3M6's greenhouse-roof line), and `tower_sold` and `tower_revoked` whether it was tagged (`tower_revoked`: A3M2's Clean Exit took it, D143); `wave_start` and `wave_cleared` may name a wave, the boss wave, or a wave that sends Everglow Security (`everglow`: Prim's PA, T603); `not_firing` may name a wave, so a line written for one wave waits for it (T330); `boss_phase` a phase; `ally_hushed` may name the hushed ally's kind, `refugee`, `bearer`, or `singer` (`HushableAllyKind`), so A3M6's bearer line waits for a bearer), plus the Act I radio's event barks that core-loop's table doesn't list yet: `bank_nudge` (D059), `enemy_leaked` (D059), `neutral_hit` (Gerald, A1M3), `tower_issued` (D061), and `menu` (entering a base screen). A bark may play `once` per map or per campaign; the save keeps once-per-campaign barks in `story.seen`.

**Optional bark button.** A bark (or radio line) may carry `button: { label: string; set?: FlagSet[]; reply?: SceneId }`, for example QUILL's Act I knock-knock joke with a "Who's there?" button. The UI rule is owned by [design/core-loop.md §6](../design/core-loop.md#6-story-facing-systems); in code:
- The button shows in the comms panel for the bark's display time and then goes away. It never pauses, never blocks input, and never changes the sim, so it isn't a `Command` and isn't in the command log.
- Pressing it emits the host event `BarkButtonPressed { barkId }`; story applies `set` and plays `reply`. Not pressing it is a valid outcome and needs no default.
- The balance harness ignores bark buttons. The forced single input ([§ Map scripts](#map-scripts-story-driven-sim-changes)) is the blocking counterpart, and the two share a visual grammar ([art-direction.md §9](../art/art-direction.md#dialogue-presentation)).

## Dialogue in play

`app/dialogue.ts` plays scenes and barks over the runner and `story/barks.ts`, and writes the views in `ui/dialogue/state.ts` (`dialogue.comms`, `dialogue.scene`) that `ui/dialogue/` draws ([art-direction.md § Dialogue presentation](../art/art-direction.md#dialogue-presentation)). `bindDialogue(host, { briefing, newTowers })` wires a battle (`app/battle.ts`).

- **Staging** (`sceneMode`): a `brief` scene is the briefing; a `scene_*` is full-screen; any other scene with a `choice` node, or flagged `pause: true` (`Scene.pause`, D134: a cue that must be read, not glanced at; A2M2's `a2_m02_cue_witch_counter`, A2M3's `a2_m03_cue_pebble`, A2M5's pivot cue `a2_m05_cue_pivot`, and A3M2's Clean Exit `a3_m02_cue_revoke`; validation keeps it to cue scenes), or a cue named in `PAUSING_CUES` (`<map>_cue_revoke`: the sim keeps ticking through the revocation, so holding the battle for Sterling is presentation's; the name and the flag never disagree, `pausingCue`), is a **pausing panel** (a choice can't wait on a panel that never blocks); it holds the sim at speed 0 until its last line and puts the speed back as it ends (the panel is opaque, and the HUD's PAUSED notice hides while it or a full-screen scene holds the battle, D135); everything else (`w<NN>`, `cue_*` without a choice, a reply) plays on the **comms panel**. A full-screen scene listed in `ui/dialogue/staging.ts` also gets a **staging** (`SceneView.staging`, D097: A1M5's stinger feed and party stage), whose clock starts as the scene opens: the stinger's camera feed plays as a lead-in before its caption types, and Next during it ends the lead-in, not the scene ([architecture.md § UI](architecture.md#ui-dom-overlay)).
- **Scenes that hold input** play one at a time (later ones wait their turn). In a battle, every one but the briefing pauses the sim with `setSpeed(0)` and puts back the speed it found as it ends (a pause the player made stays a pause). Game hotkeys are off and the HUD is `inert` while one is open; the comms panel waits, and its queue's staleness clock stops: as it frees, a scene that was already stale when the hold began is dropped, and the rest's clocks restart (D139). **It never eats a line** (D135): a scene or bark on the panel as one opens waits at the front of the queue from the line it was showing, which shows again from its start once the panel frees (its `set` nodes so far still save as it ends; having been on the panel, a countdown's start never drops it). **The one exception is a pausing cue that ends a beat** (`endsBeat`, `BEAT_ENDING_CUES`: the pivot, `<map>_cue_pivot`, D138; and the Clean Exit, `<map>_cue_revoke`, whose radio before it belongs to the shift Sterling just ended): what the panel had on screen or queued is dropped, not resumed after it (a scene cut mid-play saves what it set so far and that it was heard), so A2M5's half-read challenge or shield line never plays past her pivot. **The same drop happens for any scene that opens once the map has ended** (`mapOver`, set as `playMapEndLines` runs; D139): a flow scene before the card (A2M6's Ishael) opens only when the results hold is over, so what the panel still holds then would otherwise play over Results. A line types at 40 characters a second; Next (a click on the line or the button, Enter, or Space) finishes the typing, then moves on. The typewriter's clock is the scene's own (`nextScene`), so presses faster than the screen redraws still land one step each. A choice's options are buttons (the first focused; Up and Down move between them); in a scene with a story choice (`locksChoices`: C3's briefing, so its arrival question too, and C5's scene) the choice's group takes the focus instead, never an option, so Enter mashed through the lines lands nowhere (D143), and each option takes no press for 700 ms and after that only a fresh key-down or pointer-down (`ui/dialogue/choiceLock.ts` `choicePressAccepted`: never an Enter held through the lock, its auto-repeat; a mouse only on an option it has moved over, a tap never on the spot of the tap that brought the choice on); the pick joins the transcript as the player's line, and a C3/C4 option's "{Speaker} will remember that." shows until the next step (C5's options have none). Esc skips to the next choice (which still waits) or the end (`skipScene`). **A silence in a full-screen scene or a pausing panel moves on by itself** after its `durationSec` (2 s without one; counted from when it shows, after any lead-in), with no Next button; a click, Esc, or Enter still move on (`advancesItself`, D098: the stinger's held beat; Sterling's 2 s pause in the Clean Exit cue). A pausing panel's speakers are on the line: its lines' plates and portraits ignore who is on the radio, so a silence there is the speaker's own beat, lit, never an absent speaker's `dark` bake (only one gone for good, Bricks after A3M3, shows dark). **A staging may lock its start** (`StagingView.lockMs`, from `stagingLockMs` in `ui/dialogue/staging.ts`): for that long from its start Next and Esc are taken and do nothing (`stagingLocked`), so a scene that must be seen can't be skipped at once.
- **The briefing** is the map's `<map>_brief` scene; a map without one has no briefing. It opens as a fresh battle starts (not on Retry) and plays in the briefing modal (`ui/hud/Briefing.tsx`, styled by `briefing.css`; each run of one speaker's lines beside that speaker's face, `ui/hud/briefingView.ts` `briefingRuns`), the threat intel under it and the medals one press away, until Clock in (or Esc). It doesn't pause: the setup phase waits for the player anyway. Once it has played out, Clock in takes the focus. `hud.briefing` holds its id while it's open. A briefing waiting at C3's choice (an option that sets `door_choice` or, should a scene ever ask it there, `quill_choice`: `LOCKED_CHOICE_FLAGS`) holds: Clock in and Esc wait for the answer (`SceneView.held`), and its options take no press for their first 700 ms (`STORY_CHOICE_LOCK_MS`, dimmed meanwhile; every key-down or pointer-down while it holds restarts the 700 ms, and a choice right after another gets its own; D144), as do the scene's other choices (A3M3's arrival question, which doesn't hold Clock in); every other choice takes a press at once. It commits as the briefing closes; the battle, built before the answer, restarts on it ([meta-runtime.md § Story transactions](meta-runtime.md#story-transactions)).
- **The comms panel** plays a scene's lines in order on real-time holds: a line's reading time (4 s, plus 40 ms a character past 60), at least 2.5 s once typed, and at least its **minimum read time** once typed, 1.5 s plus 45 ms a character (`minReadMs`, D135, so a long line gets read before the next replaces it), or its `durationSec`; a line answered by the next (another speaker) holds only until 2.5 s after it's typed, and the answer shows under it with its cue kept above (D028). **The holds keep pace with the battle** (D126, `holdAtSpeedMs`): at 2× each holds half as long, but a line always stays whole on screen at least 1.5 s once typed (`RADIO_MIN_READ_MS`) and never longer than at 1× (paused, they hold as at 1×). Scenes queue behind the line on screen; one that waited more than 15 s of real time (`COMMS_STALE_MS`) is dropped (a `keep` entry never is: below), and **a countdown's radio still queued when its wave starts is dropped** unplayed (the scene already on the panel plays on). The moments that play scenes: wave NN's countdown (`w<NN>`) and a map script's `ScriptCue` (the scene with the cue's id, once a battle however many events cue it, so A2M1's crew-log line can be cued by either log or by W6; a cue naming a bark queues that bark, `cueBark`).
- **Barks** (`offerBarks`): each sim moment is offered as triggers to `pickBarkOf` over the map's pool (`barksFor`), with the battle's `BarkState` and the speakers on the radio (QUILL, a present companion, Ves'thara beside Bramble, whose every line comes through her, and Prim on a map whose waves send Everglow Security, `presentSpeakers`; on the finale's pick list the run's pick, Ves'thara whoever walks, and the choir's leader, Pebble). A bark is its own one-line scene on the panel, never under another line. Nothing plays while a line is on the panel or a scene holds input, and nothing queues: the triggers still count as fired. **Some triggers queue instead** (`isQueuedTrigger`), because their lines must never be lost: `first_leak` (QUILL's "Toward... the wilderness?", a fair-play seed), `tower_sold` and `tower_revoked` with `tagged` (Bricks on the turret he named), and `tower_built` once this run has had a revocation (`runStat` `revocations` ≥ 1: A3M2's "Build what you've got.", D143). Their bark is picked by `pickBark` ignoring the 6 s spacing (its `when`, presence, and once limits still hold), queued behind the line on the panel like a scene, and later barks keep their spacing from it. The tagged `tower_revoked` one is queued to **keep** (D144): it never goes stale and outlives the Clean Exit's beat-end drop, so Bricks's "Lucky too, huh." waits out the cue that revoked the turret however long it's read, then plays (a beat-end drop keeps it; a flow scene after the map's end still drops it). The events: `CountdownStarted` → `bank_nudge` (wave 2 on, with `BANK_NUDGE_CREDITS` = 250 banked, or the loadout's cheapest tower affordable after `BANK_NUDGE_IDLE_PHASES` = 2 build phases with no `TowerBuilt`, `TowerUpgraded`, or `TowerSpecialized` (T229; The post-game step is one named route, `toPostGame` in `app/navigation.ts`: the campaign screen, which after the finale is the post-game star map (the Sector map at dawn with the post-game plate; [core-loop.md §1.1](../design/core-loop.md#11-the-star-map), T863). **Dawn is unskippable the first time** (the flow's `unskippableFirst`: Esc does nothing until the save has seen it; Next still moves on). **"Watch the epilogue"** is `watchEpilogue()` (`app/ending.ts`; the post-game plate's button): it loads the finale's content and screens, then plays the epilogue over the save in play with Esc allowed, and resolves as it closes.
- **The finale's stages and screens** (T810; `ui/screens/`, all in the finale's screens chunk, `app/acts/finUi.ts`, loaded beside the finale's content by `app/finaleScreens.ts` through the content gate, boot's up-front load, and "Watch the epilogue"; the core holds only `ui/screens/epilogueState.ts`: the `endingScreen` signal and the registry the overlay and the staging read). **Dawn** (staging `dawn`, `dawn.ts`, `dawnStage.tsx`): T843's `scene.dawn` full-bleed at 2×, its frames turned by the narrator's lines (`DAWN_CUES`: `dawn`, then `mote` from "One gold mote rises", then `visor` from "The visor goes up", held to the end), crossfading 0.9 s (cut under reduced motion), the lines one at a time at the bottom with no history column. **C5** (staging `c5`, `c5.ts`, `c5Stage.tsx`): first light on a dark stage; the KFA's off-white form at the top files each `kfa` clause as it is said (the family line too), so the terms stay up whole through the voices and the two lines below. **The epilogue** (`epilogue.ts`, `epilogueLayer.tsx`; `credits.ts`): each card alone, centered, about 6 s (plus 40 ms a character past 120) or a click, Enter, Space, or →; then the counter, PESTS PROCESSED: 0 for 2.4 s flipping to the `final` card's REMEMBERED: {n} in gold (the cue `counter_flip`, below), held 6 s; then the credits (`ui/screens/credits.ts`, their tokens resolved for the save as the cards' are, `resolvedCredits`: the player's name over "Waykeeper") rolling up at 24 px/s (a block at a time, 2.6 s each, under reduced motion); then the final image by ending, T843's `scene.wayside` with PERIMETER STATUS: OPEN as DOM in the HUD's panel grammar over its sky (Stay), or `scene.orbit` with the relay blinking on its `blink` anim (Go; held still under reduced motion), for 12 s or a click; then the post-game. The first time through Esc skips nothing; "Watch the epilogue" closes on Esc. The layer is a modal: Tab stays on it and its keys stop there. **Audio hooks** (T850): `setEndingCuePlayer`, installed by `app/audio.ts` `installAudio`, takes the cues `counter_flip` (`ENDING_MUSIC`: `dawn_major` starts, held under the credits and the final image whatever screen is under them) and `epilogue_end` (it lets go back to the screen's music).
- **The run on screen:** from the run's end until the next battle binds, the story context carries the run that ended (`setStoryRun`, by `endRunStory`), so the full-screen scenes around Results (`content/dialogue/resultsFlow.ts`) read `outcome` and `thisRun` as the debrief does (T329).
- **`?test=1`** turns the comms panel and in-battle scenes off unless `&dialogue=1` (M2's `&radio=1` still works); the briefing still shows, whole and played out at once up to its first choice (nobody is there to pick, so the choice and what follows it don't show), with Clock in focused. `__sd.dialogue` plays a scene or bark by id (`play`, `bark`) and reads what shows (`shown`). The dev dialogue in `ui/dialogue/dev.ts` (a cue with a choice, a full-screen scene, a bark with a reply button) is never in the registries, so only the hooks play it.

## Story state

The profile, flags, seen scenes (and once-per-campaign barks), delivered and read memos, unlocked codex versions, seen enemies, `bricksTagIndex`, and `memorialTower` live in the save ([meta-runtime.md § Save system](meta-runtime.md#save-system)). Choices (D001 #3) are just flags; their payoffs are read by content (tower gifts, allies, map dressing, bark pools, epilogue cards) and by map scripts through `scriptFlags`.

## Other story systems

All pure functions over content and save state:
- `story/counter.ts`: `formatCount` ("1,234,567", locale-independent), `livePestsProcessed` (the save's count plus the run's kills), `resultsCounter(style, run, lifetime, meter?)` (the results line in the map's `counter` style, [design/core-loop.md §6.2](../design/core-loop.md#62-results-screen-and-the-lifetime-counter): Act I's line with stars and "Career total: {n}", Act II's with the career line and no stars, Act III's meter line alone (`meterCounter`) or no line at all (null) on a map with no meter, and the finale's `REMEMBERED: {n}` over the lifetime count: a post-game challenge's line and the epilogue's flip, never the finale's own card), and `countdownDisplay`, the finale countdown `round(N × (1 − restPoints / restTarget))` with progress clamped to [0, 1] ([design/maps.md §5.5](../design/maps.md#55-the-leaving-song-finale-rules)).
- `story/codex.ts`: which versions of each entry are unlocked (`unlockedVersions`, `newCodexUnlocks`), the *Pest Field Guide* / *Field Journal* title (`codexTitle`), and the versions an entry shows (`shownVersions`: the newest, or original beside corrected in the Field Journal, from A3M1). The entries are `content/codex/` (`CodexEntryDef`: an id `codex_<entry>`, a title, a kind, an optional subject, an optional picture, and each version's text, optional small print, and `when`); the act files there (`act1.ts`, `act2.ts`, `act3.ts`) are the home of the entry texts. The versions, in unlock order, are `original`, `annotated`, `margin`, and `corrected` (`CODEX_VERSIONS`). A later act's versions of an entry it doesn't own (Act II's `annotated` and `margin` of an Act I entry, Act III's `corrected`: the Brood Hauler, the Elder, and Bramble from A3M1, Gerald from A3M4, Everglow Gardens (Dome Row) and Zibzab from A3M6) are that act's `CodexLaterVersions` (`ACT2_CODEX_VERSIONS`, `ACT3_CODEX_VERSIONS`), which the registry merges in (`withLaterVersions`, in version order; a version never replaces one the entry has). An Act III entry of its own may carry both an `original` (Everglow's record) and a `corrected` that unlock together (A3M2's Buffer Protocol, Clean Exit, and Director Joy Sterling), so it opens side by side; C1's payoff is one of two entries gated on `spared_quiet_wave` (Old Thrum, or the Small Ones' Walk). No Act III entry differs by C4. The two Skitterkin gifts of part two (the Gloop Spitter, the Sproing Pad) are tower entries, unlocked when owned, so the Gloop's arrives in A3M4 or A3M6 with the door (`app/journalAct3Two.test.ts` checks every part-two entry has a way in).
  - **Revised wording** (T611): a version may carry a `revised` text with its own `when`; once that holds, the version shows the new wording in place of `text` (`versionText`) and stays the same version, in the same place beside its original. Only the Elder's correction has one: "(Survey 2346, Okonkwo.)" from A3M1, the Amended Survey's citation from A3M3.
  - **Unlock rules.** An entry with a subject unlocks when the save meets it: an enemy in `campaign.seenEnemies`, a tower or ability owned. One without (a place, a person, a thing) unlocks by its `when`, which is `{ mapAtLeast: <the map that lists it> }`, so it unlocks once that map is won (the objectives' entries are the exceptions: A2M1's crew log, `{ objectiveDone: { map: 'a2_m01', objective: 'crew_logs' } }`, and A2M4's Intake Manifest, `{ objectiveDone: { map: 'a2_m04', objective: 'intake_manifest' } }`). A later version unlocks by its own `when` once the subject is met; one with no `when` never does. Unlocks are never taken back.
  - **The context** between maps is `baseStoryContext(save)` (`meta/story.ts`): the save's flags, seen list, and lifetime count, with `map` the furthest campaign map won (null before A1M1).
  - **Annotations** (T411, T511): the note versions (`CODEX_NOTE_VERSIONS`) are notes written on the record, in two layers: `annotated` (Everglow's update or QUILL's note) and `margin` (Ves'thara's margin note, from A2M6). Each one's text is the bracketed, signed note alone. The view (`app/inbox.ts` `codexView`) carries the `original` with a note as its `record`, and the notes unlocked before it as `earlier` (`story/codex.ts` `notesShown`: the Hauler's margin note brings QUILL's), so the Codex pane shows the record dimmed, then each note under it, oldest first, behind its rule (teal for QUILL's and Everglow's, sapphire `blue.3` for Ves'thara's). The newest version on screen still shows the older ones, and a new margin note is NEW even with QUILL's note read. In the Field Journal a correction sets the original beside it and the notes step aside. An entry without a picture says `photo` in its frame ("Photo pending" by default; the withheld "Pebble" entry says "Withheld", the Long Night "Too dark").
  - **Read marks.** Opening an entry adds `codexSeenId(id, version)` (`codex_<entry>__<version>`) to `story.seen` for each version it shows; an unlocked version not there is NEW. While a version's revised wording is in force its mark is `codex_<entry>__<version>__revised` (`versionSeenId`), so the Elder's new citation is NEW once more, and the Journal tab's badge counts it.
- `story/inbox.ts`: which memos are due (`memosDue`: each memo's `afterMap` won, or null for `memo_a1_00`, and its `when`) and the gifts attached to them, a memo's paragraphs (`memoBody`: the body split at blank lines, then each `extra` whose condition holds), and the unread ones. The memos are `content/memos/` (`MemoDef`: From, To, Subject, body, conditional `extra` paragraphs, sign-off, small print, `afterMap`, `when`, `gift`, and for a form `format: 'form'` and its `stamp`); the act files there (`act1.ts`, `act2.ts`, `act3.ts`) are the home of the memo texts. From A3M2 the sender is "Everglow Automated Systems": no exclamation point, no sun, no sign-off (`memo_a3_02`–`memo_a3_06`). A memo names its letterhead as data (`letterhead`: `full` by default; `worn` for Sterling's `memo_a3_01`, Act III's colour gone but her sun kept; `automated` for the automated sender's), which the Inbox is to draw by (T713; until then `Inbox.tsx` decides by sender, so `memo_a3_01` still shows the full letterhead); `memo_a3_03` is the act file's one line and arrives at the run end that first wins A3M3, so it waits in the Inbox when the base opens after the Held card.
